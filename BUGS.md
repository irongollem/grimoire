- [x] Player with role in one campaign, DM role in another, couldn't access player portal (irongollem/grimoire#173) — `auth.loadMembership()` always loaded the user's **oldest** campaign membership via `.limit(1).order("joined_at", { ascending: true })`, so when switching campaigns the auth store retained stale role data. Router guards like `isDM` checked this stale membership, blocking a player-role user from `/play` if they had a DM role in an earlier campaign. Fixed by: (1) making `loadMembership(userId, campaignId?)` accept an optional campaign ID — if set, fetches that specific membership; without it falls back to the old oldest-first behaviour (used during initial login when `activeCampaignId` is not yet set); (2) threading the parameter through `refreshMembership(campaignId?)`; (3) calling `refreshMembership(campaign.id)` in `switchToCampaign()` to reload the correct membership when the active campaign changes; (4) passing `campaignId` to `refreshMembership()` in `JoinCampaignView` after a successful join so the auth store loads the newly-joined campaign's role (`src/stores/auth.ts`, `src/stores/campaign.ts`, `src/views/auth/JoinCampaignView.vue`)


- [x] Player calendar feed (`ical-feed` edge function) rejected unauthenticated calendar clients with 401 — Google Calendar / Apple Calendar / Outlook subscribe to an ICS URL and can't attach a Supabase JWT, so the gateway was blocking every request before it reached our code. Per-function `verify_jwt = false` was declared in `supabase/functions/ical-feed/config.toml` but the Supabase CLI doesn't read per-function configs — it reads the root `supabase/config.toml`, which didn't exist. Fixed by creating the root config with `[functions.ical-feed] verify_jwt = false` (and the same for `api-key-vault`, which has the same browser-from-anywhere access model). The function itself is already safe: it enforces access via a random per-campaign `ical_token` in the URL path and only returns CONFIRMED sessions — never draft scheduling or DM-only notes. Stale per-function `config.toml` files removed so the pattern doesn't mislead future contributors. Redeploy with `supabase functions deploy ical-feed api-key-vault` for the flag to take effect on the hosted project (`supabase/config.toml`)
