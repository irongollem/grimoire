# Provenance — the single AI-compliance system

Architecture for EPIC #611 (EU AI Act, Art 50). One system, six tickets (#605–#610)
plug into it. Register of legal positions lives in `ai-act.md` (#610); this file is
the *engineering* spec.

## Design rule

Every compliance duty is served by **one provenance core** with two write points
(server upload, client upload) and one read point (disclosure UI). No per-feature
compliance code: a generator that wants art marked or text badged uses the same
module as every other generator.

## Components

### 1. Core — `supabase/functions/_shared/provenance/`

Canonical, **pure TS** (Uint8Array in/out, no Deno/Node/browser APIs), so the same
files run in edge functions (relative import) and the browser (`@edge-shared`
alias in vite/vitest/tsconfig). Precedent for testing edge-side pure modules in
vitest: `_shared/credit-math.ts`; the vitest include glob already covers
`supabase/functions/**/*.{test,spec}.ts`. Tests colocated.

- `types.ts` — `AiProvenance { generatorType, provider, model, generatedAt, edited }`
  (single shape; DB jsonb, XMP packet and UI badge all derive from it)
- `xmp.ts` — XMP packet builder: IPTC `DigitalSourceType = trainedAlgorithmicMedia`,
  `xmp:CreatorTool`, custom `grimoire:` namespace for provider/model/generatedAt
- `embed.ts` — binary embedders: WebP (RIFF XMP chunk — fourcc `XMP` plus a
  trailing space — + VP8X flag), PNG
  (`iTXt` XML:com.adobe.xmp + CRC32), JPEG (APP1). Dispatcher
  `embedProvenance(bytes, contentType, prov)`; unknown formats pass through
  unchanged — marking must never corrupt an asset. Extractors (`readXmp*`)
  included for tests and verification.

### 2. Data model (migrations)

- `ai_provenance jsonb` column on the 13 content tables that receive generator
  output (npcs, monsters, items, spells, factions, locations, quests, traps,
  puzzles, roll_tables, encounters, notes, downtime outcomes — exact names
  verified against schema at migration time). Null = no known AI involvement.
  No backfill (unknowable; recorded in register).
- `ai_acknowledgements` — versioned consent records:
  `(user_id, kind 'ai_use' | 'likeness', version, created_at)`. Standard RLS
  four-policy set + `updated_at` trigger per CLAUDE.md.

### 3. Consent gateway = the existing `ai_enabled` toggle

Decision (Jeffrey, 4 Aug 2026): compliance couples to the "no AI" button.

- **Enabling AI** on a campaign (`AiTab.vue`) is the opt-in moment: shows the
  AI notice (interacting with AI; outputs may be inaccurate/resemble third-party
  works; where data goes) and records an `ai_use` acknowledgement. Existing
  AI-on campaigns get the same dialog once, on next generator use. Version bump
  → re-prompt.
- **Portrait flows** (Simulacrum stylize/sculpt, chronicle reference images,
  group portrait, NPC disguise) additionally require a `likeness`
  acknowledgement — enforced **server-side** in `forge-mini` and
  `generate-chronicle-image`, not just UI.
- **`ai_enabled === false` guarantee**: AI UI hidden (exists), every generator
  403s (exists). Disclosure is provenance-driven, so content generated while AI
  was on stays badged even if the toggle is later switched off — "no AI" means
  no *new* AI and no AI features, never silent unlabelling of history.

### 4. Write point A — server uploads

Generated bytes are marked **immediately before** `uploadWithRetry()`
(`_shared/storage-upload.ts`) via the core dispatcher. Callers: image legs of
generate-chronicle-image, generate-entity-image, generate-npc / location / trap,
style-map, forge-mini stylize. Server produces no resized variants, so one mark
per asset. Audio (`generate-music`): SynthID verification + register entry;
container metadata where the format allows.

### 5. Write point B — client uploads (local key mode + variants)

- Local-mode originals: mark in `uploadLocalResult()` (`src/ai/useImageGeneration.ts`)
  and the analogous entity-image local paths before `uploadToBucket`.
- Variants: `resizeToWebP()` (canvas) strips metadata — `uploadWithVariants()`
  re-embeds the XMP into every variant blob when provenance is supplied.
  User-photo uploads (no provenance arg) are untouched.

### 6. Text provenance

Generators return an `ai_provenance` block in draft JSON; save composables
persist it to the entity row. Rich-text bodies (chronicle recaps) additionally
carry `data-ai-generated` on the root element; `sanitizeHtml` preserves it.
Material human edit flips `edited: true` (never removes the record).
`useTextEnhancement` = assistive-editing exemption (register), no marking.

### 7. Read point — disclosure UI

`AiGeneratedBadge` (common component) renders from `ai_provenance` /
image-job provenance wherever the viewer isn't the generator: player portal
recap + scene art, shared minis, group portraits. Promo reuse of Chronicler
images is labelled at the marketing surface.

### 8. Log hardening (#609)

Separate wave: delta-0 rows for token-less BYOK calls, settlement-only
mutations on settled ledger rows, retention policy. Not a legal duty
(documented in #609) — evidence hygiene.
