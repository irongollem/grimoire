# Features — AI Generation

Shipped features in the **AI Generation** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Queued chronicle images — drop an anchor, keep writing** — chronicle image generation no longer blocks on the 1–5-minute render. The generate dialog now calls `startChroniclerImage()` (job id back in ~2s), drops a `pendingImage` Tiptap anchor node at the cursor (placeholder card: pulsing icon, prompt snippet, elapsed timer), clears the prompt and stays open — so 5–6 scenes can be queued back-to-back, each anchoring its own spot in the note. `usePendingImageResolver` swaps each anchor for its finished image **by job id at the anchor's live position** (typing/reflow-proof), turning failures into an inline "failed" card with Remove. Because ready `image_generation_jobs` rows persist (they are the `chronicler_images` gallery view), anchors even resolve when the note is reopened later — which also fixed the old navigate-away bug where a backgrounded render toasted "added to your note" while silently landing gallery-only. Server unchanged (async job pattern already fit); storage filenames moved from `scene-{Date.now()}` to UUIDs to kill the theoretical same-millisecond collision. BYOK local mode gets in-session anchors via `local-` pseudo-job ids. 9 new unit tests on the pure doc-scan helpers; typecheck + build green.

- [x] NPC Generator — faction picker + role, known associate picker + relationship type added to generator panel; all three (location, faction, associate) are folded into the AI prompt as grounding constraints and pre-applied to the created NPC via post-create hooks

- [x] Item Generator — AI generates magic or mundane item (name, type, rarity, description, mechanical properties) from a flavor prompt with optional type/rarity constraints; creates item directly and navigates to it; same panel pattern as Monster/NPC generators

- [x] **AI generation UX** (irongollem/grimoire#14) — rotating flavor quotes replace static pulsing across all AI generators (NPC, Monster, Item); generators moved to DefaultLayout so they survive navigation; background dismiss sends generation to a persistent badge at the bottom of the screen; generic `aiGenerationState` factory + `aiGeneratorRegistry` pattern ensures all future generators get these features automatically

- [x] **AI provider abstraction layer** (irongollem/grimoire#113) — extracted hardcoded OpenAI fetch calls into `src/ai/providers/` (`types.ts` with `TextProvider`/`ImageProvider` interfaces, `openai.ts` implementation, `index.ts` factories); all 4 generation composables now construct providers from the apiKey instead of calling fetch directly; `imageProvider.edit?` guards the NPC alter-ego disguise flow

- [x] **AI: Multi-provider support — split keys, Gemini Flash, Claude, fal.ai FLUX** (irongollem/grimoire#112, irongollem/grimoire#114, irongollem/grimoire#115, irongollem/grimoire#116, irongollem/grimoire#117) — campaigns now store a dedicated API key per provider (OpenAI, Anthropic, Gemini, fal.ai) plus explicit `text_provider`/`image_provider` selectors; `providers/index.ts` routes `getTextProvider()`/`getImageProvider()` to the correct implementation based on the active selector; Anthropic appends a JSON instruction to system prompts (no native JSON mode); fal.ai returns a URL that is fetched and base64-encoded; `decryptedApiKey` in the campaign store is a computed over the active text provider for backward compat with all generator panels; `AiTab.vue` redesigned with a per-provider key vault section plus separate text/image provider dropdowns
