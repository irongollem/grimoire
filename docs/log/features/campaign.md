# Features — Campaign

Shipped features in the **Campaign** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **The Interlude — downtime activities that become real campaign content (phase 1: Carouse)** (#486) — downtime is the most under-served part of every campaign: invisible (it lives in a forgotten Discord message), a spreadsheet of dice, and disconnected (a carousing result invents an NPC who never enters the campaign). The Interlude reframes it as an async, card-driven interlude that plays out in the player portal between sessions and whose results become **real, linked, editable campaign entities**. The loop: the DM grants a downtime credit → the player spends a draw on an illustrated archetype card → the draw lands `pending` → the DM resolves every pending draw across the party on one batch board → the outcome spawns an actual NPC in the campaign. Credits are **DM-granted only** (a "Grant downtime" button, never calendar/long-rest automation, which would yank pacing out of the DM's hands) and **per character** (`party_member_id`, since a user may own several). Balance is derived (`sum(grants) − non-cancelled draws`), never stored, so it cannot drift; `spend_downtime_draw()` derives the character from `auth.uid()` and re-checks the balance under an advisory lock, closing the double-spend race a client check cannot. The deck is **two-sided**: the DM can "stack the deck" by slotting real campaign NPCs onto the back of a card (per-archetype FIFO pile, one-shot or recurring), and when the pile runs dry it falls back to a weighted **system seed contact** (the fence, the fixer, the rival duelist…) which is cloned into the campaign as an ordinary private NPC. Outcomes _propose_ consequences the DM ticks off explicitly — the app never silently mutates a character ("the DM decides how dark their world is; we facilitate"). The archetype catalog and seeds live in `src/data/`, not the DB, so every future archetype is data rather than a migration, and are shaped card-ready so a Cardforge deck export is later a pure adapter. Pure logic (`drawFromDeck` with injected RNG, `computeBalance`) is unit-tested (28 tests); the full loop was verified against the live DB as a real player and DM with RLS active, in a rolled-back transaction. **Phase 2** generalised the reward from NPC-only to a polymorphic `DowntimeSeedReward` (`npc`/`item`/`note`) with a per-kind clone→create dispatch in `useResolveDraw` (mint the entity via `createNpc`/`createItem`/`createNote` before the RPC, hand the id in), filled the deck to **eight archetypes** (Carouse, Craft & Enchant, Research & Scribe, Train, Run a Business, Pit Fighting, Lie Low, Pull a Job) as pure data, and moved `hp` + `condition` effects from checklist to **programmatic application** alongside `gold` (pure `downtimeEffects.ts` transforms — coin never negative, HP clamped to `[0, max_hp]`, conditions case-insensitively de-duped), so `item` is now the only DM-checklist effect kind. `DeckBacksPanel` prep was generalised to slot `npc`/`item`/`note` backs. No migration — the reward-type CHECKs and `current_hp`/`conditions` columns already existed. Verified: typecheck clean, 65 downtime unit tests, live DB constraint/column confirmation. **Phase 3** shipped **AI outcome drafting** and **Card Forge deck export**, and made the whole module a **campaign-toggleable optional rule**. AI drafting: migration `20260713000001` adds the `downtime` system prompt + a `downtime_generation` credit cost, and `supabase/functions/generate-downtime/` is a **text-only** clone of `generate-trap` (the cards render procedural faces, so there's no illustration, no `entity_image` charge, and no remote-image fetch — hence no SSRF surface) that is **owner-only**, since only the DM resolves draws and a player member must never spend the owner's credits. A draft returns a `DowntimeSeed` rather than a bespoke type, so it _replaces what the deck dealt_ and travels the ordinary resolve path with zero parallel plumbing; `src/lib/downtimeAiSeed.ts` is the airlock that launders the model's untrusted JSON (it invents effect kinds, hallucinates conditions like "Hungover", and picks nonexistent item types) — drop what we can't honour, throw only on what we can't do without, never trust an `applied: true`, and fall back to `mundane` rather than to something powerful. Card Forge gained a 5th `CardSubject` kind with Inked/Modern front+back styles, accented by _risk_; the `key`-vs-`id` mismatch (`DowntimeActivity` has `key`, matching `downtime_draws.activity_key`) is owned once by `cardSubjectId()` instead of duplicating an `id` field, and the store's fragile `kind + "s"` source derivation became an explicit map (`"downtime"` is not `"downtimes"` — the mis-pluralisation would have silently dropped a bucket on collection load). The optional-rule toggle (`key: "downtime"`, default **on**, so no existing campaign loses it) hides the module from the DM sidebar and the player portal and makes both views refuse to render when off — which required **new player-nav plumbing** (`PlayerNavItem` had no `ruleKey` at all), **incidentally fixing the same latent bug for Workshop**, where players kept seeing the tab after a DM disabled crafting. Full DM Manual entry at `src/manual/interlude-overview.md` (what it is / how it works / why). Verified: typecheck clean, full suite 751 tests green, no new security advisors. **Art + go-live:** the `generate-downtime` edge function is deployed (verified rejecting unauthenticated calls), so AI drafting is live for free/platform-credit users as well as BYOK. The canonical art bucket `downtime-images` ships with an `srd/`-prefix admin-only write path and _no_ per-user upload path (every image is identical for every campaign); a follow-up migration drops the broad SELECT policy the first one inherited from `faction-images`, which on a public bucket granted no read that URLs don't already allow while letting any client **list** the whole bucket (`public_bucket_allows_listing` advisor finding — now clean). **All 21 canonical images are live and wired — 8 archetype card faces, 6 seed NPC portraits, 7 seed item images — with zero `null` art slots remaining** (the 9 note-yielding seeds get none, as `notes` has no image column; the procedural `accent`+`glyph` face stays in code as a graceful fallback). Pit Fighting's face was regenerated after the first pass put a POV fist and sword under the title scrim. Wired via (`DOWNTIME_ART_BASE` + `art()` in `src/data/downtimeArt.ts`, built from the env var rather than `getPublicUrl()` so the data files stay pure for the unit tests). **No `srd_*` table was needed** — and the earlier claim that one was _required_ was wrong: those tables exist so a DM can override canonical monster/spell art per-campaign, whereas the system deck is deliberately not overridable and its catalog lives in code, so the URL is just a string in a data file. ("SRD" was also the wrong word — none of this content is System Reference Document material; `srd/` is only this codebase's inherited label for "canonical, shared, admin-managed".) **The deck is printable, and deep enough to feel random.** Card Forge only exported the 8 _archetype_ cards — the menu a player chooses from — with no way to print what the menu yields, so a physical deck couldn't mimic the virtual one: you could lay down "Carouse" and then had nothing to draw. Added `downtime-seed` as a 6th `CardSubject` (one card per seed; front = the reward's own art + outcome title, falling back to the archetype glyph for note seeds since `notes` has no image column; back = the vignette the DM reads aloud + the proposed consequences). Both halves share one Interlude tab and one selection bucket — searching an archetype name surfaces its activity card _and_ all its outcomes, which is exactly the stack you print. Activity keys (`carouse`) and seed ids (`carouse-fence`) never collide, so one id set serves both. `describeEffect()` was extracted to `downtimeEffects.ts` so a consequence reads identically on screen and on the table. Separately, the **seed library went 22 → 48 seeds, every archetype at 6**: five of eight had only 2–3, so a player spending two draws on the same card saw the same vignette half the time (Run a Business was 62% — a coin flip, not a deck). All eight now sit at **18–20% repeat-on-two-draws**, matching Carouse (the benchmark, written first at six). **The full printable deck is 56 cards — 8 activity + 48 outcome — a 7-card stack per archetype.** Named current limits: `item` effects stay a DM checklist (and item rewards mint a catalog row rather than auto-filling inventory); the roll/loot-table engine and drop-chest delivery (the design's _optional_ branch) are left for a follow-up. **All 32 canonical images are live** (8 archetype card faces, 6 seed NPC portraits, 18 seed item images) with **zero `null` art slots** — the 24 note-yielding seeds get none, as `notes` has no image column, and render the archetype's glyph face by design. See `context/features/downtime-interlude.md` and `context/features/downtime-art-briefs.md`.
