# Features — Cartographer & VTT

Shipped features in the **Cartographer & VTT** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Traproom** — full CRUD for traps with image, type badge, trigger, detection/disarm DCs, CR+XP, save, attack bonus, damage dice (via DiceExprInput), damage type, reset type, rich description + DM notes; Assets group (no campaign scoping)

- [x] Trap HP/AC fields (physical destruction) + CR advisor (Suggest button → modal grades CR from effect category, targeting, DC tier, reset, HP/AC, secondary effects)

- [x] Add traps (created in the traproom) as elements of an encounter so their CR contributes to the total — `EncounterTraps` component in encounter builder; trap XP added flat (no multiplier) to difficulty; hazard XP shown separately in Difficulty Analysis panel

- [x] Trap detail panel in encounter runner — click a trap to inspect it; roll Detect/Disarm DCs, attack bonus, save DC, and damage dice; effect description and notes shown inline

- [x] Traproom prepopulation — "Populate Traproom" button bulk-inserts 14 classic DMG/PHB trap archetypes (pit, needle, darts, rolling sphere, collapsing roof, net, fire statue, sphere of annihilation, flooding room, glyph, alarm, mushrooms, swinging log); skips traps that already exist by name

- [x] **Multiple damage types per trap** — refactored from single `damage_type`/`damage_dice` fields to `damage_entries` array (`DamageEntry` interface with `dice` + `type`); trap editor has "+ Add" button to add multiple damage entries (e.g. 1d6 bludgeoning + 1d10 piercing); all trap templates updated to support split damage

- [x] **Enigmarium (puzzle room builder)** — full CRUD for puzzle rooms: type (Logic/Physical/Arcane/Social/Environmental), difficulty (Trivial→Deadly), setup description, ordered hints (add/reorder/remove), solution field, skill checks with DCs, success outcome + failure consequence, image with focal point, tags, DM notes; "Populate Examples" button inserts 3 curated examples (The Three Doors, The Celestial Orrery, The Waterway Vault); Assets group in nav

- [x] **Cartographer M1 — tile-based battle map builder** (irongollem/grimoire#378, epic #377) — sixth tab on `/dungeon-craft`; schema-validated WebP tile packs with per-cell hash-based variant picking; canvas editor with pan/zoom, floor brush, eraser; procedural placeholder fallback for missing assets (so the editor is usable before AI-generated WebPs land); B/E keyboard shortcuts plus W/D/S pre-wired for M2; right-mouse-drag pans without tool switch; `dungeon_maps` user-scoped table + `locations.source_map_id` FK for future Atlas baking. Walls, doors, solid blocks, undo/redo, export are queued for M2–M5

- [x] **Cartographer M2 — walls and primary tools** ([#379](https://github.com/irongollem/grimoire/issues/379)) — edge-based wall brush with hover-targeting and drag-along-edges; door tool (closed/open toggle per edge, right-click to remove); solid block layer; eraser, rectangle fill, line, flood fill, wrap-walls; full undo/redo stack; `wallJoint` corner rendering with pack palette fallback; RMB pan works in all tools including annotate

- [x] **Cartographer M3 — multi-pack support** ([#380](https://github.com/irongollem/grimoire/issues/380)) — 11 bundled tile packs (Stone Dungeon, Icy Cave, Wood Interior, Sandy Ruins, Forest, Black Rock, Lava Cavern, Underdark, Water, Sewer/Swamp, Marble Palace); per-brush pack switching mid-map; in-memory runtime cache; brightness-only jitter placeholder fallback; pack stored as `default_pack_id` on the map (note: packs are bundled in `public/` rather than Supabase Storage as originally spec'd)

- [x] **Cartographer M4 — object layer & entity links** ([#381](https://github.com/irongollem/grimoire/issues/381)) — object stamp tool with 12 object categories and per-cell rotation (Q/E keys); annotation layer with text labels and auto-focus on cell select; entity link tool wiring cells to notes, encounters, NPCs, monsters, traps, and features; cell metadata persistence; stamp rotation preview

- [x] **Cartographer M5 — Atlas baking & export** ([#382](https://github.com/irongollem/grimoire/issues/382)) — `bakeMap()` (WebP, 5 MB cap + quality retry) + `bakeMapAsPng()` (PNG, client download); view/edit URL mode matching app convention (`?edit=true`); "↓ PNG" button downloads full-res PNG; "Save to Atlas" opens location picker modal with overwrite warning; bake → upload WebP to `location-images` → update `locations.map_url` + `source_map_id`; "Edit in Cartographer" link in LocationEditor when `source_map_id` set; Cartographer added to Publishing Tools nav

- [x] **Cartographer M6 — Curves & advanced brushes** ([#383](https://github.com/irongollem/grimoire/issues/383)) — Room template tool (M) with three shape presets (circle, octagon, hex): click center, drag radius, auto-fills floor + wraps walls. Cave brush (V) with configurable size (3/5/7/9 cells) drawing organic blobs via smooth value noise; new seed per stroke for variety. Stamp rotation widened from `0|90|180|270` literal union to arbitrary degrees with `[`/`]` for ±1° fine adjustment alongside Q/E for 90°. Pack schema bumped to v2 with optional `wallRoundJoint` directional category (L_NE/L_SE/L_SW/L_NW) — renderer draws round corners at full tile size when packs supply them, falls back to standard `wallJoint` otherwise. Stone Dungeon manifest declares the new slots (procedural placeholder arcs render until real WebP art lands). New pure-functions module `src/cartographer/geometry.ts` with 13 unit tests.

- [x] **Cartographer M8 — AI Map Styler** ([#386](https://github.com/irongollem/grimoire/issues/386)) — "AI Style" button in view mode; 6 presets (Playable, Explorer's Sketch, Isometric, Tactical Grid, Ancient Tome, Woodcut Print); freeform prompt suffix; `bakeMapForAI()` downscales to 1024px PNG; `style-map` edge function calls OpenAI `images/edits`; result preview with Save to Atlas / Download / Retry / Back; `dungeongrimoire.com` watermark on all outputs; credit-charged (`map_style_generation`, 2cr default); DM guide pages added

- [x] **Shared `tokenRenderer` extracted from The Mint** ([#388](https://github.com/irongollem/grimoire/issues/388)) — `src/lib/tokenRenderer.ts` is now the single source of truth for circular token rendering; consumed by both The Mint and the upcoming VTT layer. VTT-specific options added: faction `ringColor`, `activeTurn` gold accent, `revealState: 'unseen'` silhouette, `AbortSignal` for race-safe re-renders. TokenForgeView refactored to consume it (no visual change); 8 vitest tests for silhouette + defaults + active-turn + abort.

- [x] **Battle map state model** ([#389](https://github.com/irongollem/grimoire/issues/389)) — migration `20260512000002_vtt_battle_map_state.sql` adds `encounter_state.fog_mask text` (revealed-cell mask for fog of war) and `locations.grid_calibration jsonb` (`{cells_per_image_width, origin_x_pct, origin_y_pct}`). `RunCombatant.position?: {x,y}` added in [encounter.types.ts](src/types/encounter.types.ts) for anchor-cell token positions — footprint is derived from creature size at render time, not stored. `Location.grid_calibration: GridCalibration | null` added in [location.types.ts](src/types/location.types.ts). All fields optional/nullable so existing flows are untouched.

- [x] **Grid calibration UI on locations** ([#390](https://github.com/irongollem/grimoire/issues/390)) — TDD'd pure `calibrateGrid()` in [src/lib/gridCalibration.ts](src/lib/gridCalibration.ts) (8 tests: horizontal/vertical/diagonal, non-square images, error paths). New `<GridCalibrationDialog>` (pointer-event modal, two draggable handles, dashed preview line, cells-between input, live preview). "Calibrate grid" / "Re-calibrate grid" button added to LocationEditor's map row. `useUpdateLocationGridCalibration()` mutation added to [useLocations.ts](src/composables/useLocations.ts). Cartographer Save-to-Atlas auto-populates calibration via new `computeBakedDimensions()` helper in [bake.ts](src/cartographer/bake.ts) (4 tests).

- [x] **Battle map view at /encounters/:id/run/map** ([#391](https://github.com/irongollem/grimoire/issues/391)) — TDD'd pure `battleMapGeometry.ts` (11 tests: grid line positions, cell size, origin transform). New `EncounterMapView.vue` renders the location's `map_url` as a background image with a calibrated grid overlay; cursor-anchored wheel zoom (10%–800%), pointer-drag pan, fit-to-host reset, plus explicit empty states for each failure mode (no location, no map, no calibration). "Battle Map" + new-window "↗" buttons added to EncounterRunner top bar; disabled with explanatory tooltip when prerequisites unmet.

- [x] **Auto-spawn + DM-drag tokens** ([#392](https://github.com/irongollem/grimoire/issues/392)) — `BattleMapTokenLayer.vue` renders one token per `RunCombatant` via the shared `tokenRenderer` (faction ring, reveal-state-aware, active-turn gold accent). TDD'd helpers: `sizeToFootprint` (6 tests: Tiny/Small/Medium → 1×1, Large 2×2, Huge 3×3, Gargantuan 4×4, case-insensitive, defaults to 1) and `snapPixelToCell` / `cellToPixel` (8 tests: snap-to-nearest, non-zero origin, multi-cell footprints, negative coords). Pointer-capture drag with cell-snap on drop; unplaced combatants stagger along the origin row; dead monsters render at 50% opacity; positions flow through existing `schedulePush` realtime push when live. Tokens stay anchored on pan/zoom via reactive `cellToPixel` recomputation.

- [x] **Player battle map at /play/encounter/map** ([#393](https://github.com/irongollem/grimoire/issues/393)) — `PlayerEncounterMapView.vue` mirrors the DM map view but read-only (drag disabled via empty `draggableInstanceIds`). `BattleMapTokenLayer` refactored to be fully prop-driven (combatants/factions/monsters/npcs/activeInstanceId/draggableInstanceIds/hideHidden/silhouetteUnseen passed in) so both DM and player views consume the same component. Player view filters tokens via `hideHidden: true` (hidden monsters omitted) and `silhouetteUnseen: true` ("???" silhouette for unseen monsters). "View battle map" CTA added to PlayerEncounterPanel (tablet+ only via `hidden md:flex`); mobile guard in the view redirects phones to `/play/encounter`. Also persists `grid_calibration` + `source_map_id` through generic LocationEditor saves so they survive an unrelated edit.

- [x] **Player-controlled own-token drag** ([#394](https://github.com/irongollem/grimoire/issues/394)) — RLS-safe RPC `update_combatant_position(p_encounter_state_id, p_instance_id, p_position)` (security definer) validates the caller's campaign membership, resolves their linked party_member_id from `campaign_members`, and rejects any `instance_id` that isn't `p-{linkedPartyMemberId}` before doing a jsonb_set on the matching element of `combatants_live`. Migration `20260512000003_vtt_update_combatant_position_rpc.sql`. Composable `updateOwnCombatantPosition()` wraps the RPC. PlayerEncounterMapView computes a single-entry `draggableSet` from `auth.linkedPartyMemberId` and wires `onPositionChange` to call the RPC — other players' tokens remain read-only via the same prop-driven layer.

- [x] **is_battle_map flag — prevent atlas leaks** ([#398](https://github.com/irongollem/grimoire/issues/398)) — explicit `locations.is_battle_map boolean default false` so tactical maps are hidden from `/play/atlas` regardless of `is_map_shared` (fog of war can't be bypassed by scrolling the atlas). Migration `20260512000004_vtt_is_battle_map.sql`. `LocationEditor`: "Battle map" checkbox in the map row; the "Calibrate grid" affordance only appears when the flag is set. `PlayerLocationsView` suppresses the map for battle-map locations (the location card still shows for narrative context). Runner + player panel gating extended: "Open battle map" / "View battle map" require `is_battle_map = true` in addition to `map_url` + `grid_calibration`. Empty states updated to surface "Mark this location as a battle map" when the flag is missing.

- [x] **Fog of war** ([#395](https://github.com/irongollem/grimoire/issues/395)) — TDD'd pure `fogMask.ts` (13 tests): semicolon-joined encode/decode of revealed cell keys; `roundBrushCells` (cell-centre distance check) and `cellBrushCells` (N×N centred block, even sizes clamped down); `applyBrush` (reveal / re-hide, non-mutating). New canvas-based `<BattleMapFogLayer>` fills the viewport with fog and punches holes for revealed cells via `destination-out`; DM sees translucent grey, player sees opaque black. Fog toolbox added to the DM map view: tool selector (Pan / Reveal / Re-hide), brush shape (Round / Cell), brush size (1/3/5), Reveal all / Hide all, "As player" preview toggle. Brush mode disables token drag + intercepts pan via `pointer-events-none` on the token layer. `schedulePush` extended with an optional `fogMask` field so strokes ride the existing 300ms-debounced realtime push (~300ms latency to player devices). Player view filters out combatants whose anchor cell falls in a fogged cell — even revealed monsters disappear into fog if they walk into it.

- [x] **Pre-encounter monster placement** ([#396](https://github.com/irongollem/grimoire/issues/396)) — `CombatantDef.starting_positions: Array<{x,y}|null>` (length = `count`) added to the encounter JSONB blueprint; null entries spawn at the map origin as before. New `<EncounterBattlefieldSetup>` mounts in the builder under Combatants when the linked location is a calibrated battle map: same canvas + grid + `BattleMapTokenLayer` as the runner, in build mode. Drag a token → the matching def's `starting_positions[index]` is patched + emitted up to the form. "Clear all placements" wipes every def's `starting_positions`. EncounterRunView's `initStore` seeds `combatants_live[i].position` from `def.starting_positions[i]` so the runner spawns ready-positioned tokens.

- [x] **Health info visibility** — campaign-level setting (strategic/immersive/unknown); strategic: PCs exact HP + bar, non-PCs bar + label; immersive: PCs exact, others label only; unknown: PCs exact, others nothing

- [x] **PuzzleDetailView — location / dungeon-feature anchors** (irongollem/grimoire#168) — migration `20260720000002` adds nullable `puzzle_rooms.location_id` + `dungeon_feature_id` FKs and recreates `get_player_visible_puzzles` (it `returns setof puzzle_rooms` with an explicit select list, so the new columns had to be appended — nulled, since anchors are DM prep data). Edit mode gains Location + Dungeon Feature comboboxes in the Identity card; view mode renders anchor pills linking to `/locations/:id` / `/dungeon-features/:id`.

- [x] **Traproom: multiple damage types** (irongollem/grimoire#79) — replaced single `damage_dice`/`damage_type` fields with a `damage_entries` array of `{ dice, type }` objects; each damage component has its own dice expression and type; UI shows a dynamic list editor with + Add / × remove per row; preview modal and encounter runner both render each entry; prefilled archetypes updated (Spiked Pit: 1d6 bludgeoning + 1d10 piercing, Poison Needle/Darts: piercing + poison)

- [x] **Dungeon Craft: secret door & hidden feature creator** (irongollem/grimoire#21) — new `dungeon_features` Supabase table + RLS; `src/types/dungeonFeature.types.ts` with 7 feature types (Secret Door, Hidden Passage, Treasure Chest, etc.) and 12 trigger types; `useDungeonFeatures` composable; list view with search + type filter at `/dungeon-features`; create/edit form with Discovery DCs (Perception / Investigation / Arcana), trigger mechanism, contents, description, image upload, and DM notes; "Dungeon Craft" nav entry in Assets group

- [x] **Dungeon Craft: unified tabbed interface** — consolidated `/dungeon-features`, `/traps`, and `/puzzles` into a single `/dungeon-craft` hub with three tabs (Features/Traps/Puzzles); old routes now redirect to tabbed view with query param; each tab has its own populate button and create action; `DungeonCraftView.vue` orchestrates tabbed navigation, action visibility, and API state per tab

- [x] **Dungeon Craft: random encounter / roll tables** (irongollem/grimoire#120) — new `roll_tables` table (campaign-scoped JSONB entries) + RLS, `useRollTables` composable family, `RollTableDetailView` with a range editor that validates 1–N coverage + an inline roller that highlights the matching entry. Entries reference `encounters` so the DM can link to a fully-built fight scenario from any roll, with a free-text fallback for results without an Encounter row yet. The Encounters page's "Unassigned" filter widens to `quest ∪ roll-table` membership via a new `useEncountersInRollTables()` set — encounters cited by either a quest or a roll table no longer show as unassigned. Seeded with 4 example tables (low-level dungeon, forest road, underdark patrol, coastal cliffs) via the populate button. Integrated as a fourth tab on `/dungeon-craft`.

- [x] **Dungeon Craft: loot tables** (irongollem/grimoire#121) — new `loot_tables` table (campaign-scoped JSONB entries) + RLS, `useLootTables` composable family, `LootTableDetailView` with an Item Vault picker per row, a per-item drop chance (1–100%), and a quantity input that accepts either a fixed integer or a dice expression (`2d4`, `1d6+2`). Roll panel walks every entry, rolls the d100 drop chance, then rolls the quantity for hits — produces a tidy summary like "32× Gold Piece · 2× Potion of Healing · Longsword +1". CR-tier metadata (`any` / `0–4` / `5–10` / `11–16` / `17+`) lets the DM filter the list to the right tier in the moment. Integrated as a fifth tab on `/dungeon-craft`.
