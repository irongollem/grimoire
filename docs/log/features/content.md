# Features — Content & Import

Shipped features in the **Content & Import** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Licences & Attributions — the compendium stops calling other publishers' books "SRD"** ([#567](https://github.com/irongollem/grimoire/issues/567)) — we hosted ~6,700 shared entries from 21 source documents while reproducing no licence text and recording no licence on nearly any row. Only ~660 of ~3,540 shared monsters are actually WotC SRD; the rest is Kobold Press and EN Publishing material whose licences require accurate attribution, and OGL 1.0a §10 requires the licence text travel with the content. New **`content_sources`** catalogue (migration `20260729000002`) holds the per-document facts — `title`, `publisher`, `license_keys`, `copyright_notice`, `product_url`, `is_redistributable`, `is_metadata_curated` — because they are per-document, not per-row: copying a copyright line onto 3,500 monsters would be 3,500 places for it to drift. New **`get_content_licenses()`** RPC (`SECURITY INVOKER` — every shared table is already world-readable, so a definer function would buy nothing but an advisor finding) returns one row per source actually present with per-kind tallies; its `LEFT` join is deliberate, so an uncatalogued source surfaces as "Uncatalogued source" rather than vanishing from the page whose job is proving nothing is unattributed. New **Licences tab** in both the DM (`/rules?tab=licenses`) and player Reliquary, listing every source grouped by licence with counts and product links, then the licence texts themselves: the OGL 1.0a in full from `src/data/ogl.ts` (machine-extracted verbatim from the Open Gaming Foundation's canonical copy — sections 1–14 render as-is; **section 15 is rebuilt at render time** from the `copyright_notice` of every OGL source present, because §6 requires the chain to name each work we copy), plus the ORC License's required notice and the CC-BY credits. **Research corrected two beliefs we had wrong**: Black Flag is **ORC**-licensed per Kobold Press's own announcement, not the CC-BY-4.0 Open5e tags it (their taxonomy has no ORC entry, so they bucketed it to the nearest one) — 360 monsters were about to be published under the wrong licence; and Tal'Dorei is **verified OGL 1.0a** (Green Ronin, 2017, exact §15 line from the book's own legal page), so those 4 monsters stayed rather than being deleted. Wizards' SRD 5.1 line is "Copyright 2016", not the 2023 date commonly quoted second-hand. Ingestion is now gated: `REDISTRIBUTABLE_LICENSE_KEYS` + `isRedistributable()` refuse any document with an unknown licence **or none at all** (unknown licensing is a refusal, never a default-allow), and `assertRedistributableDocuments()` makes an explicit `npm run seed-srd-monsters <key>` fail as firmly as `--all` — previously any key could be seeded with no check whatsoever. The monster/item/species mappers now populate `source_license` (it was hardcoded `null`); the embedded `document` ref on v2 records omits `licenses`, so a `Map<string, Open5eDocumentRef>` from the new `fetchOpen5eDocumentRefs()` is threaded through, matching what the spell importer already did. New `scripts/seed-content-sources.ts` refreshes machine-derived fields only — a `Pick` type makes it structurally impossible to construct a payload containing `copyright_notice`, and `is_metadata_curated` rows are skipped wholesale so a re-seed can never revert Black Flag's ORC correction. Nine `source_document_key` values are stale pre-v2 Open5e slugs (`cc`→`ccdx`, `menagerie`→`a5e-mm`, `dmag`→`deepm`, `blackflag`→`bfrd`, `taldorei`→`tdcs`…), so `LEGACY_DOCUMENT_KEY_ALIASES` maps between them — any data-driven backfill skipping it matches nothing. Backfill set `source_license` on every shared row (2,525 monsters OGL, 360 ORC, 656 CC-BY; the only remaining nulls are our own 25 class rows, which correctly carry no third-party licence). A follow-up pass ([#576](https://github.com/irongollem/grimoire/issues/576), migration `20260729000004`) then found the missing §15 lines in a place the API never exposes: **Open5e's own repo carries a `copyright` field per document** (`data/v1/<key>/Document.json`) — their compiled §15 text, which powered the retired v1 API and which **v2 dropped entirely**. That is also the correct chain to be in, since we copy Open Game Content from Open5e. 13 of the 16 OGL/ORC sources now carry the publisher's verbatim line, reproduced exactly as published including what look like our typos and aren't (`Tome of Beasts.` for the 2023 edition, `©2022` with no space, `Briand Suskind`). It also settled a conflict — Creature Codex had two competing verbatim lines, and Open5e's names the product correctly with an author list matching their live v2 data, unlike Kobold Press's Midgard-page subset — and **independently confirmed the ORC call**: Open5e's Black Flag fixture carries an ORC notice rather than a §15 line, which is exactly why their ORC-less taxonomy mislabels it `cc-by-40`. Only `dmag-e`, `warlock` and `kp` keep descriptive notices, because no product-specific line exists to copy (upstream holds only `"© Open Design LLC"`/`"Various"`, and `kp` is a publisher-wide catch-all whose linked policy is a fan-content Community Use Policy with no §15 text). Throughout, an unverifiable notice states only what is verifiable rather than a plausible-looking year and author list — a fabricated copyright line is worse than an incomplete one. The tab also covers **audio**, which no part of the issue mentioned: the soundboard ships 802 sounds and **82 of them are CC-BY**, requiring credit that until now appeared only on a sound's card after a DM added it to a board. New `get_audio_licenses()` (migration `20260729000003`) groups `sound_library` by `(license, source)` and gathers the per-sound credit lines — kept out of `content_sources` on purpose, since audio attribution is per-sound and each row already stores a ready-made credit line, and flattening the two shapes into one table would lose that. `attributions` is null rather than `[]` for CC0 groups, because "no credit required" and "credits went missing" must not render identically. Full suite green: 1,724 tests / 147 files, vue-tsc + build clean, zero new security advisors.

- [x] **Shared SRD items & species — the compendium stops living in every DM's account** (#303) — the last two per-user SRD import paths (items, species) moved to shared, admin-seeded tables, completing the `srd_monsters`/`srd_spells` pattern. Instead of 300+ duplicated item rows and 9 duplicated core races per DM, `srd_items` (1717 rows: 548 `srd-2014`, 808 `srd-2024`, 361 edition-neutral grimoire-bundled gear/provisions/services/ammunition) and `srd_species` (the 9 core species per edition) are public-read/admin-write, seeded by two new service-role scripts (`npm run seed-srd-items` / `seed-srd-species`) that **reuse the exact browser mappers** the in-app flows use — the species mapper was extracted from `SpeciesOpen5ePanel.vue` into `src/lib/open5eSpeciesImport.ts` (16 tests), and `toTiptapJson` was un-duplicated into `src/lib/markdownToTiptap.ts` (a supabase/Pinia-free lib both the panel and the Node seed script can import). `useItems()`/`useAllSpecies()` now merge the shared tables with the user's own rows under a **shadowing rule**: a custom row hides its shared twin by `(source_document_key, source_record_key)` identity, or — critically, because **every one of this account's 2014 existing item rows predates the identity-stamping migration and has NULL identity keys** — by lowercase name as a fallback, so existing vaults show zero duplicates with no data migration and nothing deleted. The bundled mundane gear that the retired per-user import wrongly stamped `2014` is now `ruleset: null`, so 2024 campaigns finally get their mundane gear. **Existing campaign data was the hard constraint and is provably intact**: item references (`store_items`, `party_inventory`, recipes, npc/faction inventory, loot tables, quest rewards, encounter loot, downtime deck backs, chat vendor offers/drops) stay hard `uuid` FKs into `items`, and every DM-side picker now calls a new `useEnsureOwnedItem()` bridge that clones a picked shared row into the user's table (idempotent by source identity, unique-violation-race-safe) before persisting an id — so a text slug can never reach a uuid column; a post-migration integrity sweep found **0 orphaned inventory/store references and 0 unresolved species refs**. Species references (`party_members.species_id`/`disguise_species_id`, `campaigns.disabled_species_ids`) became `text` (migration `20260724000003`, with an `AFTER DELETE` trigger replacing the dropped FKs plus scrubbing the campaign blocklist) so a player can pick a shared species directly during character creation without cloning; `useSpecies(id)` resolves either a uuid or a slug transparently, and shared rows render read-only with a "Clone to customize" action. The 255 already-seeded item art rows survive twice over: the seed script backfills them into `srd_items.image_url` by lowercase name (one name → both edition rows) **and** the client-side `srd_art_defaults` merge still applies at read time, so no linked image was lost (60 leftover art rows are for non-default-document content that only appears under a `--all` seed, not orphans). Per-campaign gating reuses `campaign_enabled_sources` (new `get_srd_item_sources`/`get_srd_species_sources` RPCs; the Vault gained the same Sources panel as Monsters/Spells), and the admin "Publish all my SRD art" flow chains a new `sync_srd_item_art_to_shared_table()`. Along the way three near-duplicate "Sources" popovers (Monsters/Spells/Items) collapsed into one `SourcesPickerPanel` and the duplicated admin SRD-art block into `SrdArtPublishPanel`. Filed [#566](https://github.com/irongollem/grimoire/issues/566) for a pre-existing gap surfaced during verification (per-campaign species/class blocklists aren't enforced in player self-service creation). Full check suite green: vue-tsc clean, 1203 tests, build 2.2s, no new security advisors (the new SECURITY DEFINER RPCs carry the same `anon`-executable advisor note as their monster/spell siblings, by design). Contract in `docs/srd-reimport.md`; feature docs updated.
