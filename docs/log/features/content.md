# Features — Content & Import

Shipped features in the **Content & Import** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Shared SRD items & species — the compendium stops living in every DM's account** (#303) — the last two per-user SRD import paths (items, species) moved to shared, admin-seeded tables, completing the `srd_monsters`/`srd_spells` pattern. Instead of 300+ duplicated item rows and 9 duplicated core races per DM, `srd_items` (1717 rows: 548 `srd-2014`, 808 `srd-2024`, 361 edition-neutral grimoire-bundled gear/provisions/services/ammunition) and `srd_species` (the 9 core species per edition) are public-read/admin-write, seeded by two new service-role scripts (`npm run seed-srd-items` / `seed-srd-species`) that **reuse the exact browser mappers** the in-app flows use — the species mapper was extracted from `SpeciesOpen5ePanel.vue` into `src/lib/open5eSpeciesImport.ts` (16 tests), and `toTiptapJson` was un-duplicated into `src/lib/markdownToTiptap.ts` (a supabase/Pinia-free lib both the panel and the Node seed script can import). `useItems()`/`useAllSpecies()` now merge the shared tables with the user's own rows under a **shadowing rule**: a custom row hides its shared twin by `(source_document_key, source_record_key)` identity, or — critically, because **every one of this account's 2014 existing item rows predates the identity-stamping migration and has NULL identity keys** — by lowercase name as a fallback, so existing vaults show zero duplicates with no data migration and nothing deleted. The bundled mundane gear that the retired per-user import wrongly stamped `2014` is now `ruleset: null`, so 2024 campaigns finally get their mundane gear. **Existing campaign data was the hard constraint and is provably intact**: item references (`store_items`, `party_inventory`, recipes, npc/faction inventory, loot tables, quest rewards, encounter loot, downtime deck backs, chat vendor offers/drops) stay hard `uuid` FKs into `items`, and every DM-side picker now calls a new `useEnsureOwnedItem()` bridge that clones a picked shared row into the user's table (idempotent by source identity, unique-violation-race-safe) before persisting an id — so a text slug can never reach a uuid column; a post-migration integrity sweep found **0 orphaned inventory/store references and 0 unresolved species refs**. Species references (`party_members.species_id`/`disguise_species_id`, `campaigns.disabled_species_ids`) became `text` (migration `20260724000003`, with an `AFTER DELETE` trigger replacing the dropped FKs plus scrubbing the campaign blocklist) so a player can pick a shared species directly during character creation without cloning; `useSpecies(id)` resolves either a uuid or a slug transparently, and shared rows render read-only with a "Clone to customize" action. The 255 already-seeded item art rows survive twice over: the seed script backfills them into `srd_items.image_url` by lowercase name (one name → both edition rows) **and** the client-side `srd_art_defaults` merge still applies at read time, so no linked image was lost (60 leftover art rows are for non-default-document content that only appears under a `--all` seed, not orphans). Per-campaign gating reuses `campaign_enabled_sources` (new `get_srd_item_sources`/`get_srd_species_sources` RPCs; the Vault gained the same Sources panel as Monsters/Spells), and the admin "Publish all my SRD art" flow chains a new `sync_srd_item_art_to_shared_table()`. Along the way three near-duplicate "Sources" popovers (Monsters/Spells/Items) collapsed into one `SourcesPickerPanel` and the duplicated admin SRD-art block into `SrdArtPublishPanel`. Filed [#566](https://github.com/irongollem/grimoire/issues/566) for a pre-existing gap surfaced during verification (per-campaign species/class blocklists aren't enforced in player self-service creation). Full check suite green: vue-tsc clean, 1203 tests, build 2.2s, no new security advisors (the new SECURITY DEFINER RPCs carry the same `anon`-executable advisor note as their monster/spell siblings, by design). Contract in `docs/srd-reimport.md`; feature docs updated.
