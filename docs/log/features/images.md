# Features — Images & Art

Shipped features in the **Images & Art** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] Focal point support for items and spells — `image_focal_point` jsonb column added; `ImageUpload` uses `show-focal-point` mode matching NPC/monster pattern

- [x] Portrait image swapping on paper doll — replaced SVG character placeholder with real portrait images; swaps between `/assets/dressed.webp` and `/assets/naked.webp` based on whether the clothes slot is equipped; smooth opacity transition on swap

- [x] Smart image cropping — `FocalImage` component with smartcrop.js content-aware analysis + localStorage cache; three canonical formats: `portrait` (2:3), `landscape` (9:4), `token` (1:1 circle)

- [x] Manual focal point override — `FocalPointPicker` component; click-to-set stored per entity in DB (`portrait_focal_point` on NPCs, monsters, companions)

- [x] Companion portraits — upload, focal point, auto-fill from linked monster/NPC source; token avatar in DM companion card

- [x] Standardised image displays — NpcList, MonsterList, CardForge (all 8 card types), PartyTracker, TokenForge, and player portal all use FocalImage with the correct format

- [x] Shared `ImageUpload` component — unified dashed drop zone, drag-and-drop, optional focal point picker, bucket cleanup on replace/remove; used across all 8 upload locations (NPCs, monsters, items, spells, party members, locations, traps); `card_art_focal_point` added to monsters table + SRD art overlay

- [x] Egress optimisation — WebP conversion on upload (canvas, max 1920px, 85% quality); `FocalImage` lazy-loads all images (`loading="lazy"`); Supabase Pro image transforms (resize + WebP at CDN edge) gated by `VITE_SUPABASE_TRANSFORMS=true`; client-side infinite scroll (48/page, IntersectionObserver) on Monster, NPC, and Item lists

- [x] Art Library cross-bucket browser — `ArtPickerModal.vue` lets DMs browse every uploaded image across 12 per-entity buckets (NPC, Monster, Location, Chronicle, Document, Item, Spell, Faction, Pantheon, Loot, Trap, Puzzle), pick one, and have its full-resolution URL inserted directly into Tiptap rich-text content. Wired into Scriptorium block picker ("Browse photos…") and CoverPageInspector. Display uses w200 thumbnails with `@error` fallback to the original; click emits the original URL so prints stay full-quality

- [x] Per-entity image bucket separation — two new buckets created (`pantheon-emblems` for deity portraits + holy symbols + pantheon emblems, `loot-images` for loot table chest illustrations) so the catch-all `asset-images` no longer absorbs uploads from forms with their own clean home. `ImageUpload.vue` `bucket` prop is now required so future call sites can't silently fall back to asset-images

- [x] **Unified generation Gallery** (`/gallery`, Assets nav) — an account-wide library of every AI-generated image, tabbed by kind (Chronicle, NPCs, Monsters, Items, Spells, Factions, Locations, Maps, Traps, Puzzles, …) with prompt search and click-through to the source entity. Backed by `image_generation_jobs`: a shared `useImageGenerationLog()` helper writes a `ready` row (kind, image_url, prompt, target entity link) from every generator client-side — NPC/location/trap create panels, the cartographer map restyle, and on-demand entity-art regen via a new `aiTargetId` prop on `EntityImageBlock` (threaded through ~10 detail/edit call sites); chronicle images already logged server-side appear via the same table. New `GalleryView.vue` (FocalImage grid, lightbox, per-tile delete) + `useGalleryImages.ts` (RLS owner-scoped, active-campaign filtered); tab/search state in `useUiStore`; migration `20260609000001` drops the `kind` CHECK (kinds now owned by the `IMAGE_GEN_KINDS` TS const) and adds a `(user_id, status, created_at)` index. Historical pre-log entity art is not backfilled (still browsable via the bucket-based Art Library)

- [x] Reduce egress — NPC/Bestiary/Item lists were loading full-size images for every card with no pagination:
  - [x] Lazy-load images via `loading="lazy"` on `FocalImage` — browser skips off-screen images entirely
  - [x] Infinite scroll (48/page, IntersectionObserver) on Monster, NPC, and Item lists — limits DOM + image requests on initial load
  - [x] WebP conversion on upload — all new images stored as WebP (max 1920px, 85% quality) reducing source file size for all downstream use
  - [x] Pre-generated image variants — `uploadWithVariants()` in `storage.ts` fans out 4 static size variants (`_w200/_w300/_w400/_w600.webp`) at upload time; `FocalImage` derives the variant URL from the stored original URL and falls back to the original via `@error` for pre-existing images; `VITE_SUPABASE_TRANSFORMS` and the Pro plan `/render/image/` API removed entirely; Card Forge keeps full-res originals via `print` prop; `asset-images` (Scriptorium embeds) excluded from variant generation; 1100 existing images backfilled via a one-shot edge function (now deleted)
  - [x] `api-key-vault` decrypt caching — `decryptApiKey()` was firing a cold edge function call on every `switchToCampaign()` (app load, PlayerLayout mount, every campaign save); session-scoped `Map` cache in `apiKeyVault.ts` makes all repeat decrypts free; `primeDecryptCache()` lets `AiTab` seed the cache immediately after encrypt so the following `switchToCampaign` is also a no-op

- [x] **Illuminator: texture overlay + blend modes** (irongollem/grimoire#269, part 2) — new `src/lib/textureOverlay.ts` with `applyTextureOverlay` (tileable, uses canvas globalCompositeOperation); blend modes: Multiply, Screen, Overlay, Soft Light, Hard Light; Opacity + Tile Scale sliders; compact drop/upload area in new "Texture Overlay" accordion section; wired into preview + full-res export pipeline (after DoF, before Vignette)

- [x] **Monetization: Downgrade flow — graceful pro→free transitions** (irongollem/grimoire#304) — `user_subscriptions` extended with `cancel_at_period_end` + `cancel_at` columns (webhook syncs on `customer.subscription.updated`); `campaigns` extended with `is_archived` boolean; `useCampaigns` filters to active campaigns, adds `useArchivedCampaigns`, `useArchiveCampaign`, `useRestoreCampaign`; `DowngradeCampaignPickerModal` auto-shown in `DefaultLayout` when active campaigns exceed free-plan limit after cancellation; `CampaignSwitcher` shows archived campaigns with Restore button; `BillingView` shows pending-cancellation warning with cancel date + per-resource downgrade impact summary (what will be locked, not deleted); locked content overlays added to all five quota-gated list views (NPCs, Monsters, Encounters, Notes, Scriptorium — newest over-quota items locked deterministically by `created_at` ascending); fixed hardcoded "Up to 3 campaigns" (now reads from `freePlan.value?.quotas.campaigns`).

- [x] **Simulacrum — portrait → 3D miniature pipeline, Phases 0–3.5** (plan: `SIMULACRUM_PLAN.md`; feature doc: `context/features/simulacrum.md`) — built via overseer pattern (Sonnet builders + Fable review). DB: `minis` (the row IS the job — status machine + Realtime), `feature_interest`, `simulacrum_config` (`hidden|teaser|live`), service-role-write-only `mini-models` bucket, `mini_sculpt` credit row (500), guarded no-op pg_cron poller skeleton (migrations `20260718000001–3`, advisor-clean). Backend: `forge-mini` edge fn (stylize/sculpt/resculpt/cancel/delete; **platform keys only — no BYOK by design**; reserve-then-settle; free re-sculpts capped at 2, `sculpt_count <= 3`), `poll-meshy-jobs` cron poller (downloads all formats into our bucket immediately — Meshy deletes assets after 3 days), `_shared/mesh3d.ts` Meshy client with `MESHY_MOCK=1` fixture mode, pure state machine in `_shared/simulacrum.ts` (57 vitest tests). Frontend: forge wizard (Format → Stylize → Sculpt/Preview via lazy `@google/model-viewer`), `/minis` gallery (ui-store filters), "Mini" button on NPC/monster/PC portrait blocks (Vitruvian icon), admin mode panel + interest counter, and the **teaser demand gate** ("the ritual fizzles" + notify-me → `feature_interest`). Overseer review caught 3 integration bugs pre-merge: a state-machine dead end (post-sculpt re-stylize could never sculpt again), a delete-mid-sculpt credit-reservation leak, and the sculpt step firing the paid action where the free retry applied. Edge fns deployed with `MESHY_MOCK=1` (end-to-end testable via the `mock` platform-key recipe); minis are generated **baseless** with `auto_size`+bottom origin — we supply the base (25mm plinth-generated library + composition + real-mm scaling = Phase 4.5, #542). NOT live: Phase 4 (Meshy sub, real key, poller secrets, `live` flip) per the go-live checklist in the feature doc; print partners = #541.
