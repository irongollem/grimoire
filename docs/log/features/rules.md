# Features — Rules Reliquary

Shipped features in the **Rules Reliquary** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Optional class features (Tasha's swaps) — foundation** — general mechanism for DM-authored "optional class feature" swaps that replace a default PHB feature and may grant always-prepared spells (e.g. a Ranger's **Primal Awareness** in place of Primeval Awareness, granting Speak with Animals at 3rd, Speak with Plants 9th, Locate Creature 13th, Commune with Nature 17th). Adds a `tashas_optional_features` campaign gate (`src/rules/optionalRules.ts`, DM-only, default off — the "we own the book and allow it" switch). New owner/campaign-scoped `class_feature_options` table (migration `20260725000001`), modelled on `custom_subclasses`: `granted_spells jsonb` reuses the `{ "<level>": ["<spell_id>"] }` shape, plus `replaces_feature`, `available_at_level`, and free-cast config (`free_cast_uses`/`free_cast_resets_on`/`casting_ability`/`grant_source_type`); owner-write RLS + campaign-member select via `private.is_dm_of_my_campaigns`, `updated_at` trigger, security advisors clean (no new findings). Because Tasha's is non-SRD/proprietary, options are **private per owner** (never seeded into the shared `system_*`/`srd_*` tier) — DMs who own the book author their own, mirroring custom subclasses. Grants land on `character_spells` as `always_prepared` rows, which are exempt from the spell-list (`validate_character_spell_source`) and prepared-limit (`validate_character_spell_limits`) guards, carrying `source_label` for provenance. Applied live to the Icewind Dale campaign: the Primal Awareness option plus Speak with Animals on the Beast Master ranger. **Phase 2 pending** (not yet shipped): `buildLevelUpPayload` wiring so the swap grants automatically on level-up, a "manage optional features" surface for retroactive adopt/drop on existing characters, and a spell-UI enhancement — the player spell UI partitions innate (non-`class`) vs prepared (`class`) rows by `source_type`, so an always-prepared row's free-cast uses are stored but not yet displayed. Beast Sense (5th level) is omitted — it is absent from the SRD spell set (Open5e's import skips it).

- [x] Dual-edition conditions & exhaustion (#556) — condition data split per-edition (`src/data/srdConditions2014.ts` SRD 5.1, `src/data/srdConditions2024.ts` SRD 5.2) with a `CONDITION_PATCHES` override/fill-gap layer (`src/data/conditionPatches.ts`) applied last by `getConditions()`/`getCondition()` in `src/lib/conditions.ts`; Open5e has no structured 2024 condition data yet (open5e-api#793 — confirmed live: `/v2/conditions/` is all 2014-tagged with empty `desc`, `/v2/rules/?document__key__in=srd-2024` doesn't carry the Conditions appendix), so every 2024 entry currently lives in the patch map, each flagged `// TODO verify against SRD 5.2 PDF`. `scripts/fetch-srd-conditions.mjs` now takes `--edition=2014|2024` and regenerates either file (2024 will start finding real entries once upstream ships them). Exhaustion mechanics now branch by ruleset: 2014 keeps its per-level disadvantage ladder (`hasAttackDisadvantage`/`hasCheckDisadvantage`/`hasSaveDisadvantage`, all now also correctly triggered by 2014 exhaustion — attack-roll disadvantage from exhaustion 3+ was previously missing entirely); 2024 uses a flat `getExhaustionD20Penalty` (−2×level to every d20 Test) and `getExhaustionSpeedPenaltyFt` (−5 ft×level), wired into the character sheet's ability/save/skill/attack rolls and condition badges. All condition tooltips (character sheet, party panel, companion cards, encounter runner, condition pickers) now resolve edition-correct text via `useRuleset()`

- [x] **Contextual DM Manual links — a "?" on every section header** — the DM Manual (Reliquary → Manual tab) already deep-links via `/rules?tab=manual&page=<id>`, but nothing in the app pointed to it, so it sat undiscovered. Added a reusable `ManualHelpLink.vue` (small `IconInfo` `RouterLink`, styled to match the existing ad-hoc tooltip-button convention) and a new `title-suffix` slot on `PageHeader.vue`/`ListPageLayout.vue`, then wired it into all ~25 top-level DM views plus five headerless bespoke top bars (NPC Relationship Web, Encounter Runner, Encounter Map, Card Forge, Campaign Chat) and the Rules Reliquary's own tab bar. Dungeon Craft, Character Codex, and the Reliquary itself get one icon whose target is **reactive to the active tab** (`MANUAL_PAGE_BY_TAB` maps) rather than one icon per tab, so the link always points at exactly what's on screen without cluttering the tab bar. Filled every content gap this surfaced: 13 new manual pages (NPC Sets, Vault overview, DM Screen, SRD Compendium, Soundboard, Party Tracker, Gallery, Hall of Heroes, Campaign Settings, Billing, Character Sheet export, Campaign Chat, Campaign Notes, Encounter Map), following the existing frontmatter/tone conventions exactly. Also fixed a latent bug found along the way — `CampaignSettingsView.vue` passed `PageHeader` a `:subtitle` prop that component never defined (should've been `:description`), so the active campaign's name silently never rendered under the title. Separately cleaned up **6 orphaned view files** (`TrapsView`, `PuzzlesView`, `FeaturesView`, `CustomClassListView`, `CustomSubclassListView`, `ChatView`) — each superseded by a consolidated tabbed view and confirmed unreferenced by any route or component before deletion; their redirect routes are untouched.

- [x] Hidden condition + player Hide action — added a 16th, non-SRD **Hidden** entry to the shared `CONDITIONS` list (`src/lib/conditions.ts`) with edition-aware rules text in `CONDITION_PATCHES` (2014 + 2024, since Open5e has no such condition). It's a full shared condition — it appears in the DM's condition picker and renders as a chip everywhere. On the player Combat tab (`PlayerCombatTab.vue`) a **Hide** action rolls Dexterity (Stealth) and, on a completed roll, marks the character Hidden; the card doubles as a live "Hidden / Reveal" indicator so players can see at a glance whether they're hidden. Making any attack auto-clears Hidden (5e RAW — attacking reveals you). The Stealth math was extracted into a shared, unit-tested `skillCheckBonus` (`src/lib/skillCheck.ts`) now used by both the Skills tab and the Hide action.

- [x] Turn Timer optional rule — a per-campaign combat rule that puts a soft countdown on each combatant's turn. The DM sets the duration (default 60s, 5–600) in Campaign Settings → Rules; a shared visual countdown (`TurnTimer.vue`) shows in the runner top bar and on every player's encounter panel and resets on each turn (reset-key = round + active combatant). It flashes amber under 10s and pulses red at 0 but never force-ends a turn. Introduces the general "configurable optional rule" mechanism: a nullable `config jsonb` on `campaign_rules` (migration `20260724000006`), a `config` field on `OptionalRuleDef` with `RuleConfigField` descriptors, `resolveRuleConfig()` (defaults-merge) + `useSetRuleConfig()` in `useOptionalRules`, and number-input rendering in `RulesTab.vue`

- [x] Random Initiative Each Round optional rule — when enabled, every combatant's initiative is silently auto-re-rolled (`store.reshuffleInitiative()`, no physical-dice prompt) and the order re-sorted at the start of each new round, with the turn handed to the top of the fresh order. Driven from the runner via `store.setRandomizeInitiativeEachRound()` watching the campaign rule, so it can be toggled mid-fight and takes effect on the next round wrap (`src/rules/optionalRules.ts`, `src/stores/encounterRun.ts`, `src/components/encounters/EncounterRunner.vue`)

- [x] **Immersive Rolls**: Campaign-level toggle in World Settings. When on, certain player skill checks (stealth, knowledge, insight, investigation, medicine, survival) post only flavor text to public chat; DM receives the full result via private whisper; player does not see their own dice result — promoting immersion for hidden info scenarios
