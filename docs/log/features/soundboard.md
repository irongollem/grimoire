# Features — Soundboard

Shipped features in the **Soundboard** area, newest first. Part of the Grimoire feature log — see the [log index](../index.md).

- [x] **Ambient scenes stack** (irongollem/grimoire#572, phase 2 leftover) — `activeAmbientPlaylist` was a single ref and `playAmbientPlaylist` opened by stopping whatever was running, so a DM could have a tavern **or** rain and never both. That was never a design decision, only the shape one ref forced. Scenes are now a list: starting one adds it alongside the others, because rooms stack — rain over a tavern, a forge under a market. Stop, pause and resume all take an optional playlist id and default to "all", so a card, the palette and the scene mixer each scope to their own scene while Stop All still means everything. A layer already audible in another scene is skipped rather than started twice, since there is one element per sound and a second copy would just play over itself at double volume with nothing to tell the two apart. `activePlaylistId(type)` is replaced by `activeMusicPlaylistId()` plus `isPlaylistActive(id)` / `isPlaylistPaused(id)` — with several scenes running, "is the ambient slot busy" no longer answers "is this card playing". `SceneMixer` renders a section per scene with its own stop button, since the global Stop All is too blunt once two are up: pulling the rain should not also close the tavern. Themed triggers follow the same split — music is exclusive and hands its slot back on release, ambient is purely additive, so a location only ever removes the scene it started and combat ending leaves the room the party is standing in alone. Also checked and dismissed the sibling "scenes do not crossfade" item: `playAmbientPlaylist` already fades the outgoing scene out over `AMBIENT_FADE_MS` while the incoming one fades in over the same window, so replacement has been crossfading since phase 1. 1592 tests.

- [x] **Encounters and locations drive the audio, bound by theme label** (irongollem/grimoire#572, phase 5) — `useSoundboardStore` was imported only by soundboard's own files: starting a fight didn't start combat music and a location had no soundscape, which is exactly the claim the marketing page leaned on. Audio now binds by **theme label**, never by a foreign key to one playlist — an encounter asks for `battle` and any music playlist tagged `battle` is a candidate, picked at random, so tagging three playlists once gives every future combat variety. A dedicated track per encounter is the prep burden this deliberately avoids. Migration `20260728000001` adds `soundboard_playlists.tags` (GIN-indexed), `encounters.audio_theme` and `locations.audio_theme`. **Slots compose**: an encounter drives `music`, a location drives `ambient`, so dungeon ambience keeps running underneath battle music and neither can contend for the other's channel — the resolver will not look in the other slot even when its own has no answer. The governing rule, and the one the tests exist to protect: **a trigger that finds no match does nothing at all** — it never stops, fades or replaces what is already playing, because silence the DM chose beats silence we chose, and a feature that hijacks the room the first time it guesses wrong gets switched off forever. Releases only take effect from whoever currently owns the slot, so a stale encounter ending cannot cut the music a newer one started; on release the slot goes back to whatever the DM had running beforehand. Built as an event bus (`src/lib/audioTriggers.ts`) rather than direct store calls: combat has no idea which playlists exist or whether themed audio is even on, and every future producer would otherwise grow the same dependency. Encounter audio fires on **Start Combat**, not Go Live — Go Live is about the player portal, and most tables running this are in one room. Walking between two themed locations requests the new one before releasing the old, so the ownership guard performs the handoff instead of a stop-start between rooms. Shared `ThemeInput` (free text with datalist suggestions — `EntityCombobox` is a strict id-picker and structurally cannot offer a label that doesn't exist yet, which a DM needs when labelling the encounter before building the playlist). DM toggle lives in the shared `SoundboardMixer`, so it reaches both surfaces. 1582 tests.

- [x] **Fire-by-search palette and a real hotkey registry** (irongollem/grimoire#572, phase 4) — the feature's own pitch is "buttons you can hit without looking away from the table", and every one of them was a mouse target on a grid that scrolls. Two halves. (1) **`src/lib/hotkeys.ts` + `useHotkeys`** replace the pattern where every shortcut in the app opened its own `document` keydown listener with nothing aware of what anything else had bound — `GlobalSearch`, `ImageLightbox`, the cartographer editor. One shared listener, layered (`overlay` hard-suppresses `page` and `global`, so an open palette cannot fire board sounds behind it), with a dev warning on collision and `useActiveHotkeys()` feeding a cheat sheet that cannot go stale because it is not hand-maintained. Matching is exact on modifiers, so a bare `1` does not fire on Cmd+1, and skips text-entry targets including tiptap's `contenteditable`. `GlobalSearch` migrated onto it, so `mod+K` is now visible to the registry rather than invisibly claimed. (2) **`SoundPalette`** — `mod+shift+K` from any page, since the point is firing a cue from the encounter you are running without navigating away. Ranked by `src/lib/soundSearch.ts`: exact, prefix, word-prefix, substring, over name then tags then artist, deliberately **not** fuzzy — subsequence matching is impressive right up until it plays the wrong thing in front of six people. Playlists and scenes rank above loose sounds. Enter on a one-shot effect re-fires it from the top rather than pausing, because hitting the thunderclap twice should give you two thunderclaps; it stays open so you can fire several in a row. On the board itself: `1`-`9` fire the first nine cards **in rendered order** with the number shown on the card, plus space (pause/resume everything), arrows (track, master volume), `m`, `x`. Space yields when a button has focus, so one press never does two things. New store actions `pauseAll`/`resumeAll` keep your place instead of tearing the session down — the doorbell case, where Stop All costs a playlist position and a whole scene. Also extracts `useSoundPlayback`, so the palette cannot offer a WebM file to a Safari user that the card already knows to disable, and moves the `playlist_type` branch into the store, where it was being repeated four times per surface. 1549 tests.

- [x] **Scene mixer and layer editor — the visible half of scenes** (irongollem/grimoire#572, phase 2) — the layers of a running scene were unreachable: you could stop the whole thing, but not pull the rain down under the tavern. New `SceneMixer.vue` lists the running scene's layers with a fader each, writing to that scene's own remembered level so it never disturbs how the sound behaves elsewhere; generator layers are badged, since their fader sets the ceiling each random firing is drawn against rather than a currently-audible level. Mounted inside the shared `SoundboardMixer`, so it appears on **both** the page and the widget for free. `PlaylistTrackRow` gains a collapsible layer editor for ambient playlists: loop-vs-generator toggle, level, firing interval range, quietest/loudest range, and stereo spread. The range inputs keep min ≤ max as you drag either edge, because crossing them would persist a pair the DB check constraints reject and fail the entire save. Track saving now carries layer settings end to end (`PlaylistTrackInput`), spreading over `DEFAULT_LAYER` so music playlists simply take the column defaults.

- [x] **Scenes: per-layer levels and random one-shot generators** (irongollem/grimoire#572, phase 2) — ambient playlists were a stack of loops all playing at whatever volume the sound carried globally, so a DM could not sit rain under a tavern without permanently changing how rain sounded everywhere else, and a three-loop tavern was the same three loops every time until players started hearing the seam. Migration `20260727000002` gives every track a `layer_volume` plus generator settings. A layer can now be a **generator**: instead of looping it fires a one-shot at an interval drawn uniformly from `[min_interval_s, max_interval_s]`, at a level drawn from `[min_gain, max_gain]`, panned randomly within `pan_spread` via a new `StereoPannerNode` in each sound chain (`engine.setPan`). That variation is the point — a mug clattering somewhere on the left every forty-odd seconds, never at quite the same level or place, reads as a room; the same file on a loop reads as a recording. Generators deliberately do not fire on scene start, since a scene where every one-shot lands at once announces itself as a machine. `setLayerVolume` adjusts a layer live. Pause tears down timers but keeps generator config so resume can rebuild, rather than forgetting it. 46 store tests.

- [x] **Sound providers behind an adapter, so libraries can be swapped** (irongollem/grimoire#572) — Freesound was wired straight into the browser component, which made it a single point of failure: provider terms change, APIs get deprecated, and commercial-use questions can land badly. Introduces `src/lib/soundProviders/` with a `SoundProvider` contract, a `ProviderHit` shape the UI actually speaks, a registry, and a `freesound` adapter holding every Freesound-specific detail (licence vocabulary, attribution wording, the preview-URL CDN rewrite). Licences normalise to `public-domain` | `attribution`; anything an adapter cannot map onto those must be filtered out rather than represented, because a commercial product should not be guessing at an obligation it cannot describe. `SoundFreesoundBrowser` became `SoundProviderBrowser` and no longer names Freesound anywhere — label, minimum query length and attribution note all come from the provider. Adding a library is now one adapter plus one registry line; removing one is deleting a line. 11 tests.

- [x] **Mixer shared between both soundboard surfaces** (irongollem/grimoire#572) — the mixer shipped into the floating widget only, so `/soundboard` itself gained nothing visible from the whole engine phase; a DM looking at the page saw no change at all. Extracted `SoundboardMixer.vue` and mounted it in **both** `SoundboardView` and `SoundboardWidget` (a `collapsible` prop folds it behind a disclosure in the widget, where vertical space is scarce, and shows it inline on the page). Also stopped defaulting the widget mixer to collapsed — a small grey disclosure row is indistinguishable from "nothing changed". The rule going forward: the two surfaces show the same board, so any new control belongs in a shared component rather than inline in one host, or they drift and the DM learns a control exists that they then cannot find.

- [x] **Gapless looping for ambience beds** (irongollem/grimoire#572, phase 1) — `audio.loop` is not gapless in any browser, so every cycle of a tavern or rain bed had an audible click or gap; one of the most obvious "this sounds amateur" tells in the feature. Ambient scene layers now play as a **pair of alternating elements**: the partner is pre-created and buffered when the scene starts, and `ontimeupdate` crossfades to it one `LOOP_CROSSFADE_MS` before the audible half ends, so the wrap is covered by an overlap instead of exposed. The halves swap roles each cycle, and the outgoing one is parked at position zero ready to be the incoming one next time. Chose dual-element over decoding to an `AudioBufferSourceNode` because a three-minute stereo bed decodes to roughly 70 MB and ambient scenes layer several at once — buffer looping would blow up memory exactly where gapless matters most. Degrades to plain `audio.loop` when Web Audio is unavailable (nothing to crossfade with) or when duration never resolves (live streams), and if the browser refuses to start the second element it falls back to a seamed loop rather than letting the bed stop dead. The shadow half deliberately owns no `playbackState`, so it never appears in the UI or double-counts the playing badge. Pause/resume and stop tear down or rebuild both halves.

- [x] **Convolution reverb, and effects at bus and master level** (irongollem/grimoire#572, phase 1) — two related fixes. (1) All six presets were lowpass-only, so `cave` and `sewer` sounded merely muffled; a space is defined by its reflections, not by losing its highs. Added a **single shared `ConvolverNode`** on a send bus (one per page, not one per sound) with per-sound and master sends. Impulse responses are **generated procedurally** — exponentially-decaying stereo noise, progressively damped so the tail dulls like a real room — rather than bundling IR files, which sidesteps the third-party licensing questions the project is careful about elsewhere. Occlusion presets (door/wall/distant) stay near-dry because they describe sound being *blocked*; cave and sewer send heavily, with different decay lengths so they are distinguishable. IRs are cached by decay length. (2) `setEffect` only ever coloured one sound, so selecting "cave" left the music bed and every other layer dry — acoustically backwards, since walking into a cave affects everything audible. Buses and master now each carry their own `BiquadFilterNode` (`sound → busFilter → busGain → masterFilter → masterGain`), with new `setBusEffect` and `setMasterEffect`. The three levels **compose** rather than clobber: a bard behind a door, heard across the room, in a cave. Master effect is surfaced next to the Master fader in the widget Mixer. 33 engine tests (up from 22).

- [x] **Per-sound loudness trim, and a SoundCard split to make room for it** (irongollem/grimoire#572, phase 1) — `sounds.gain_trim` had a column, engine support and a store setter but no UI, so the correction was unreachable. `SoundCard.vue` was at 608 lines (over the 600 soft max) and is the natural home for it, so it was split first: a 76-line orchestrator that routes on `source_type`, plus `SoundCardHeader` (thumbnail, inline name/artist/category, badges, loop, delete), `SoundCardSpotifyTransport` and `SoundCardAudioTransport` (the two mutually-exclusive playback modes), and the new `SoundTrimControl`. Faithful extraction — no markup or class changes. Trim is a persisted per-sound correction (0.25×–4×, matching the DB constraint) deliberately styled apart from the volume slider, since "set once and forget" and "ride during the session" are different jobs: `@input` previews live through the engine while dragging, `@change` persists once on release. A trimmed sound shows a gold `Trim 1.40×` badge so adjusted sounds are spottable at a glance. Also fixes a touch bug inherited from the artist placeholder it mirrors: both used `text-muted-foreground/0` revealed via `group-hover`, which never fires on a touch device, leaving the affordance invisible and undiscoverable on the tablet a DM actually runs this from at the table. Both now show at low opacity on non-hover devices.

- [x] **Mixer UI: master and per-bus faders in the widget** (irongollem/grimoire#572, phase 1) — the faders added with the bus graph had no UI, so a DM could not actually reach them. Adds a collapsible **Mixer** section at the foot of `SoundboardWidget` with a Master fader plus Music / Ambience / Effects bus faders, showing the master percentage inline while collapsed. Bus labels dim when master sits at zero, so a fader that cannot currently be heard says so. Also extracts `VolumeSlider.vue`: the same range-input markup had been copied four times across `SoundboardWidget` and `SoundCard` (per-sound and Spotify in each), and the mixer needed four more — all six now share one component with `label`/`showPercent`/`wide`/`muted`/`accent` props. Separately splits `src/lib/soundTransport.ts` out of the store (element registry, duck refcounting, transition generations, category→bus mapping), taking the store back from 736 to 681 lines.

- [x] **Web Audio bus-graph engine: fades, crossfade, ducking and a master fader** (irongollem/grimoire#572, phase 1) — every transition used to be a hard cut, because volume ran through `audio.volume` (pre-context) which cannot be ramped as an `AudioParam`, and every sound built its own private chain straight to `ctx.destination` so there was no master or group level at all. New `src/lib/audioEngine.ts` replaces that with `source → filter → soundGain → bus(music|ambient|effects) → master → destination`, and `src/stores/soundboard.ts` is rewired onto it. Gains: fade-in on play and fade-out before pause/stop; a real crossfade on music-playlist advance (triggered from `ontimeupdate` while the outgoing track is still audible, with the next element pre-created so its fetch and decode precede the transition rather than leaving a silence gap); auto-ducking of the music and ambient buses while an `effects` one-shot plays, ref-counted via a Set so overlapping one-shots don't un-duck each other; master and per-bus faders (`setMasterVolume`/`setBusVolume`), neither of which existed before; and per-sound `gain_trim` loudness normalisation (migration `20260727000001`) so a quiet Freesound clip and a loud upload can be levelled once instead of the DM riding a slider every session. Ramps pick exponential only when both endpoints clear a silence floor, falling back to linear so a fade-out reaches true zero rather than stalling at an epsilon. A generation counter guards the fade-out completion callback so a stop immediately followed by a play can't have the stale callback pause the freshly started element. Also consolidates the two `AudioContext` singletons that had drifted apart (the store's private one and `src/lib/audioContext.ts`, used by dice and the turn chime) onto the shared module. 49 tests across `audioEngine.test.ts` and `soundboard.test.ts`; the store's public API is unchanged for all nine consumers, with category and gain-trim carried as optional trailing params.

- [x] **AI music generation in soundboard via Lyria 3** (irongollem/grimoire#352) — "Generate" tab in `SoundForm` (visible when Gemini API key is configured); text-prompt → Lyria 3 API (clip $0.04 or full-song $0.08); generated audio piped through `useSoundUpload` → stored in `sounds` bucket as a normal sound; `logUsage()` called after successful generation with `model = lyria-3-{variant}` so cost appears in admin AI usage stats; `ai_model_pricing` seeded with per-variant flat costs (migration `20260506000004`).

- [x] **Soundboard playlists** — `soundboard_playlists` (music | ambient, shuffle, repeat) and `soundboard_playlist_tracks` tables with RLS + triggers; `PlaylistCard` and `PlaylistsPanel` components; music playlists play tracks sequentially (auto-advance on `onended`, next/prev with 3s restart threshold), ambient playlists layer all tracks as independent looping sounds; per-track and playlist-level controls in `SoundboardWidget`; `MusicPlaylistRunState` / `AmbientPlaylistRunState` in `useSoundboardStore`.

- [x] **Soundboard: Media Session / CarPlay integration** — `useMediaSession` composable wired from `App.vue`; music playlist tracks register `navigator.mediaSession` metadata (title, artist, album = playlist name, artwork = thumbnail or app icon) and action handlers (play/pause/nexttrack/previoustrack/stop/seekto); playback state and scrubber position kept in sync; ambient playlists excluded (no single current track); no-ops on browsers without Media Session API.

- [x] **Soundboard: sound thumbnails and artist field** — `sounds` table gains `thumbnail_url` (migration `20260522000003`) and `artist` (migration `20260522000004`); new `sound-images` storage bucket (5 MB, WebP/JPEG, public) with per-user RLS; `SoundCard` header shows a 32×32 clickable thumbnail square (upload via `useSoundThumbnailUpload` → WebP conversion → `sound-images` bucket; old thumbnail deleted from storage before replacement); artist is inline-editable below the track name with a hover-only placeholder when empty; both fields flow into the Media Session metadata for CarPlay / lock screen display (artist defaults to "Dungeon Grimoire" when not set).

- [x] **Soundboard page/board UX polish** — five quality-of-life fixes to board (page) and track management. (1) **Move sounds between boards**: the `SoundCard` page picker dropdown no longer hides once a sound is assigned (dropped the `!sound.page_id` gate) — it shows whenever more than one board exists, with the current board preselected, so a sound can be reassigned freely via the existing `useMoveSound` mutation. (2) **Edit track category after creation**: the category label in `SoundCard` is now click-to-edit (same pattern as the inline name/artist editors), revealing a small select (Ambient / Music / Effects / Misc) that saves immediately via `useUpdateSound` — previously category could only be set at creation and was effectively locked to its default. (3) **New board auto-focus**: creating a page now focuses _and_ highlights its title input for immediate typing; the old `nextTick` ran before the refetched `pages` prop rendered the new tab, so `addPage` now stashes `awaitingFocusId` and an `orderedPages` watcher fires `focusRenameInput()` once the tab actually renders. (4) **Tab overflow handling**: "All" and "Add Page" are pinned while the named tabs scroll horizontally in the middle (`flex-1 min-w-0 overflow-x-auto` on the `VueDraggable` container, native scrollbar hidden via new `scrollbar-none` `@utility` in `main.css`). (5) **Overflow cues**: edge fade + chevron buttons (`canScrollLeft`/`canScrollRight`, recomputed on a direct `scroll` DOM listener + `ResizeObserver` + tab-set changes) appear only when there's hidden content in that direction and click to scroll; a 1px tolerance against max scroll hides the right chevron correctly at the very end. All in `SoundboardPageTabs.vue` + `SoundCard.vue`.
