- [x] **px→rem audit (the #462 4th item, resolved as a policy + sweep)** (irongollem/grimoire#462) — the deferred "3270 px vs the rem-only rule" item, closed by converting every _scalable_ length to rem/Tailwind tokens and keeping px only where it is genuinely correct. **Markup arbitrary utilities (deterministic codemod, 307 files, 1594 sites):** `text-[Npx]` → design tokens where an exact match exists (`text-[10px]`→`text-2xs` ×1158, `12`→`text-xs`, `14`→`text-sm`, `16`→`text-base`, `20`→`text-xl`) and rem otherwise (`9`→`text-[0.5625rem]`, etc.); `w-/h-[26px]`→`w-6.5`/`h-6.5` (Tailwind v4 dynamic scale); `grid-cols-[240px_1fr]` and `w-/h-/max-h-[min(…px,…vw)]` track/box sizes → rem; `rounded-[calc(var(--radius)-2px)]`→ native `rounded-md`. **`<style>`-block + inline-style px (112 responsive-UI files, via 5 parallel Sonnet subagents):** font-size / width-height / padding-margin / gap / positional offsets / border-radius → rem; **kept px** for borders/outlines, box/text/drop-shadows, `@media`/`@container` breakpoints, `9999px` pills, hairline dividers, SVG user-space `<text>` sizes, and JS-computed pixel coordinates (`x + 'px'`). **`main.css`:** `--radius-md/-sm` calc deltas → rem; the iOS-anti-zoom `font-size: 16px` input rule, tooltip-arrow border-geometry, and shake-keyframe jitter left px. **Deliberately excluded (px is correct — "px where needed"):** the 50 fixed-dimension print/export artifacts — Card Forge card styles (a card is literally `200×280px`), the `794px` A4 character sheets, and the Paged.js Scriptorium themes — since these must not rescale with the reader's browser font. Net: ~1780 px removed; the ~1360 that remain are all legitimate keeps. Verified: `vue-tsc` clean, production build clean. (A follow-up issue tracks turning the now-consistent rem sizes into a semantic typography system — `text-eyebrow`/`text-body`/etc. bundling family+size+weight — migrated block-by-block.)

- [x] **Semantic typography system — role-keyed text tokens** (irongollem/grimoire#552, follow-up to #462) — the repeated `font-* + text-* + tracking-*` recipes are now 11 named `@utility` roles in `main.css`, adopted at **4360 call sites** over five block-by-block sweeps. **Cinzel labels:** `text-eyebrow` (10px, uppercase overline, 403) / `text-label` (10px, mixed-case action & field labels, 708) / `text-label-lg` (12px section & field headings, 908). **Body (Crimson Pro):** `text-body` (14px default reading, 1040) / `text-caption` (12px fine print, 944) / `text-caption-sm` (10px densest, 158). **Cinzel headings:** `text-heading-sm`/`text-heading`/`text-heading-lg`/`text-title`/`text-display` (199). Every token is byte-equivalent to the classes it replaced — line-height resolves through `var(--tw-leading, …)` exactly like the built-in `text-*` utilities, verified against the built CSS so an explicit `leading-*` still wins — so the whole migration is a **no-op except one deliberate step**: the in-between sizes left by #462 (7/8/9/11/13/15px) were rounded onto the standard scale per the ratified ramp, shifting ~430 sites by 1–2px and bringing arbitrary `text-[<n>rem]` to **zero app-wide**. Roles are keyed by **role, not size**, because a size can't bundle a family (10px is 1285 Cinzel vs 150 fell; 12px is 1386 vs 841) and weight isn't uniform either (only ~433 of 1500 10px sites carry an explicit weight) — a token bundles only what is genuinely uniform for that role, so `font-weight`, `italic`, `uppercase` (outside eyebrow) and colour stay separate classes. **Two deliberate non-actions:** tracking variance is _not_ normalised — sampling showed the ~1110 untracked Cinzel sites aren't drift but two roles where zero letter-spacing is correct (interactive `button`/`select`/`input` at small sizes, `h1`–`h3` display type at large ones), so adding tracking there would have restyled 1110 buttons and headings for nothing; and the ~927 Cinzel _control_ sites are left untokenised because their real debt is the absence of shared button components (component-granularity), which a text token would only paper over. Codemods were token-set-scoped to `class=""` values and `@apply` bodies with whole-token matching; a first pass that matched the `class="` inside `:class="` and de-duped a ternary's repeated `<`/`?`/`:` corrupted one expression — the production build caught it, the tree was reverted, and the matcher was hardened (negative lookbehind rejecting `:class`/`v-bind:class`, no blind de-dupe, expression guard on quotes/`?`, multi-line values skipped for hand review). Typecheck + production build verified green after every block.
