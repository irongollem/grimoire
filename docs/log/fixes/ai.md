# Fixes — AI Generation

Resolved bugs in the **AI Generation** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] Admin Providers tab queried each provider's model list (`list-provider-models`) unconditionally on mount, even for providers with no API key configured — every such load threw a noisy 422 (`no_key`) in the network tab and console for no benefit, since the query can never succeed without a key. `isActive` was previously hardcoded to `computed(() => true)`; replaced with a per-provider `isKeySet(provider)` computed (already used elsewhere on the page to gate the UI) passed as the `enabled` ref to `useProviderModels`, so each model-list query now only fires once its provider's key is actually set, and reactively enables the moment a key is added. (`src/components/admin/AdminProvidersTab.vue`)

- [x] Chronicle text silently truncated mid-sentence (e.g. cutting at `**Bolan` right before the quoted nickname `"B.B."`) — the generators requested `{"chronicle": "..."}` via OpenAI JSON mode, whose constrained decoding lets the first **unescaped quote inside the narrative** legally terminate the JSON string; the decoder then closes a syntactically valid object and the API reports a clean stop (ledger showed 924 output tokens — no cap hit, no error, half a chronicle). A JSON wrapper around a single free-text field was pure risk with zero benefit: removed JSON mode from all three providers (OpenAI `response_format`, Anthropic's appended JSON instruction, Gemini's `responseMimeType`), updated the live `chronicle_text` system prompt row to "output ONLY the narrative — no JSON wrapper", and made both the edge function and the client local-BYOK path tolerate either shape during the transition (unwrap the legacy `{chronicle}` if a model still emits it, else pass plain markdown through). Deployed as generate-chronicle-text v16. (`supabase/functions/generate-chronicle-text/index.ts`, `src/ai/useChroniclerTextGeneration.ts`, `ai_system_prompts` row `chronicle_text`)

- [x] AI NPC portrait + alter-ego disguise generation was silently broken since `b2b4e444` (2026-06-09, "selectable image model + Google Nano Banana"). That refactor changed `generate-npc/index.ts` to import only `resolveImageProvider` from `_shared/imageGen.ts` and dropped the `generateImage` import. The function separately declares a local `let generateImage: boolean` (from the `generate_image` request field), so the two `await generateImage({...})` call sites were invoking a **boolean** — `TypeError: generateImage is not a function`. Both sit inside `try/catch` blocks that log `"Portrait generation failed"` and continue as non-fatal, so every NPC came back portrait-less with no user-visible error and no alert. Fixed by importing the real `generateImage` and renaming the flag to `shouldGenerateImage`. Found by `deno check` after consolidating the Edge Function import map — the error had been masked by 96 unrelated cross-version type errors. NOTE: edge function — requires `supabase functions deploy generate-npc` to take effect. (`supabase/functions/generate-npc/index.ts`)

- [x] `generate-entity-image` could call OpenAI with a null API key — the text-provider `if/else` chain guards `anthropicKey` and `geminiKey`, but the final `else` fell through to `openaiText(openaiKey, ...)` where `openaiKey` is `string | null` (reached when the campaign has no OpenAI key and no platform key is configured). That sent `Authorization: Bearer null` and surfaced as an opaque upstream 401 rather than a clear "no key configured" message. Now throws a descriptive error before the call; the surrounding `try/catch` already turns it into a clean JSON error and releases the reserved credits. Fixed without `?? ""` coercion, which would have re-hidden the absence. (`supabase/functions/generate-entity-image/index.ts`)

- [x] Async chronicle image jobs could spin "pending" forever with no terminal state, and the wait gave no expectation-setting — a slow render was indistinguishable from a hang. The worker (`generate-chronicle-image`) runs in an Edge isolate via `EdgeRuntime.waitUntil()`; if that isolate is killed before writing the result, the `image_generation_jobs` row stays `pending` indefinitely (nothing swept it). Separately the client poll timed out at 5 min, but real `gpt-image` renders can take ~5 min — observed a job finish at 4:56, i.e. it nearly false-failed a job about to succeed. Fixes: (1) pg_cron sweep (`fail-stale-image-jobs`, every 5 min) flips any job `pending` >10 min to `failed` with a clear error — the single authority for stuck jobs, so every job reaches a terminal state (migration `20260613000004`); (2) client poll timeout raised 5→8 min and the client no longer mutates job status (observer-only, so it can't clobber a late server success), with a calmer, actionable timeout message (`src/ai/useImageJob.ts`); (3) escalating reassurance copy in the generate dialog ("usually 1–3 min" → "still working, you can close and keep working" → "taking longer than usual but still running") so a long render reads as normal; (4) the dialog's Cancel button was `:disabled` during generation, trapping the user on a spinner — since the job runs server-side (or in-tab for BYOK) and the dialog stays mounted in NoteEditor, it now stays enabled and relabels to "Close — keep generating": closing backgrounds the render (it still drops into the note via the `generated` emit and into the gallery) instead of trapping or aborting; (5) backgrounded renders (dialog closed) had no inline feedback, so completion/failure now surface via `useToast` — success ("Chronicle image added to your note.") or error — but only when `!props.visible`, so it doesn't double up with the inline error while the dialog is open. (`supabase/migrations/20260613000004_fail_stale_image_jobs_cron.sql`, `src/ai/useImageJob.ts`, `src/components/notes/ChroniclerGenerateDialog.vue`)

- [x] Local-mode BYOK keys were sent to providers un-decrypted, breaking all client-side AI generation (chronicle, NPC, location, trap, image). In "store keys locally on this device only" mode, `loadProviderKeys` read `localStorage[grimoire_<provider>_key]` verbatim into the `decrypted*` store refs with no decryption step — the cloud/DB path always decrypts via the edge function, but the local path assumed the stored value was plaintext. Any user whose localStorage held a legacy/migrated `enc:v1:` blob (e.g. carried over from a prior cloud-mode setup) had that blob sent straight into the `Authorization: Bearer …` header, so the provider rejected it. Fixed by making the local-mode read decrypt-on-read: if the stored value starts with `enc:v1:`, call `decryptApiKey()` and rewrite localStorage with the plaintext, so providers (which send `Bearer ${apiKey}` verbatim) always get a usable key. Self-heals existing stuck local-mode state. (`src/stores/campaign.ts`)

- [x] Chronicle scene-image generation returned `422 (Unprocessable Content)` surfacing in the browser as `net::ERR_FAILED` — the **deployed** `generate-chronicle-image` edge function was still the old BYOK-only version (`v2`) that only read `campaign.openai_api_key` and 422'd when none was set. After the move to platform ("remote worker") keys, the campaign no longer carries a BYOK key, so every request hit the 422. The rewritten version (platform-key fallback via `fetchPlatformKeys`, async job pattern, credit deduction) existed only locally and had never been deployed; the frontend (`useChroniclerImageGeneration.ts`) was already on the `job_id` polling path. Fixed by deploying the local function (`v3`). Also patched the early-return error responses (401/403/404/405/422 and the "no key" 422) to include `corsHeaders` so future errors are readable in the browser instead of being blocked as CORS failures (`supabase/functions/generate-chronicle-image/index.ts`)

- [x] Spell image generation biased all art toward campaign setting theme (e.g. every spell looked frost-flavoured in a frozen-world campaign) — `settingPrompt` was appended to the image generation prompt even though the LLM had already incorporated setting context into `result.image_prompt` during text generation, causing the raw setting string to act as a style directive; fixed by removing `settingPrompt` from the image prompt concatenation in `useSpellGeneration.ts`

- [x] AI item generation: curse details leaked into the public description, and magic item benefits were vague flavour text instead of concrete D&D 5e mechanics; fixed by tightening the `ITEM_SYSTEM_PROMPT` description field to explicitly forbid curse references and require mechanical precision (e.g. "+1 to attack and damage rolls", spell names with recharge) (`src/ai/prompts.ts`)

- [x] `api-key-vault` Edge Function blocked by CORS on every request — Supabase JS client sends `x-client-info` and `apikey` headers that weren't listed in `Access-Control-Allow-Headers`; also returned 401 because default JWT verification conflicted with the project's lock-free session cache. Fixed by expanding allowed headers to `*` and deploying with `--no-verify-jwt` (security relies on `VAULT_KEY` env secret, not user identity).
