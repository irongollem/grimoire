# Fixes — Cartographer & VTT

Resolved bugs in the **Cartographer & VTT** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] Player battle-map — wrong active-turn highlight + token snap-back (#531 & #532, both High). (#531) `PlayerEncounterMapView.activeInstanceId` indexed the fog-filtered, definition-order `liveCombatants` list with `active_combatant_index`, but that index addresses the **initiative-sorted** order (how `encounterRun` computes turns) — so the gold "active turn" ring highlighted the wrong token or none. Extracted the canonical comparator into `src/lib/combatantSort.ts` (`sortCombatantsByInitiative`/`compareCombatantsByInitiative`, with vitest tests) — it was duplicated in `encounterRun.ts` and `PlayerEncounterPanel` and now the map — and the map sorts the full list before indexing, matching by `instance_id`. (#532) `pushState` **full-replaced** `combatants_live` with the runner's in-memory `state.combatants`, whose positions are seed values (null for players, `starting_positions` for monsters) — the main runner window never ingests the position writes the map windows make via `update_combatant_position` (separate `window.open` Pinia context). So any player/DM token move snapped back the instant the DM changed HP/turn/condition. Fixed `pushState` to read the live `combatants_live`, build an `instance_id → position` map, and merge those positions onto the outgoing combatants (DB position wins) before writing — moves now persist across pushes. `vitest` (6 new) + `vue-tsc -b` ok. (`src/lib/combatantSort.ts`, `src/lib/combatantSort.test.ts`, `src/views/play/PlayerEncounterMapView.vue`, `src/components/player/PlayerEncounterPanel.vue`, `src/stores/encounterRun.ts`, `src/composables/useEncounterLive.ts`)
