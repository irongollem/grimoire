# Fixes — Factions

Resolved bugs in the **Factions** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] `FactionDetailView` kept showing the wrong faction after clicking a related-faction link (#492) — the view called `useFaction(id.value)`, passing the **unwrapped** string, and `useFaction` built a **non-reactive** query key `["factions", id]`. Since `App.vue` renders `<RouterView/>` with no `:key`, the component instance is reused on same-route param changes, so navigating `/factions/A → /factions/B` via a relation link (`FactionRelationsSection`) never remounted the view: `id` recomputed to B but the frozen query key stayed on A, leaving the header, `FactionSheet`, and every `:faction-id`-driven sub-section rendering faction A while the URL read B. Fixed by making the composable reactive — `useFaction(id: MaybeRefOrGetter<string>)` with a `computed` query key + `toValue`, matching the already-correct `useMonster`/`useNpc`/`useLocation`/`useItem`/`useQuest`/`useSpell` pattern — and passing the reactive `id`. Also fixed the three latent siblings with the identical non-reactive-id pattern (not yet reachable via sibling links, fixed for consistency): `useRule`/`RuleEditView`, `useCraftingRecipe`/`CraftingRecipeView`, and `useEncounterLive`/`EncounterRunView` (the last is not vue-query, so it also gained a `watch` on the resolved id to reload live state on id change). (`src/composables/useFactions.ts`, `useRules.ts`, `useCrafting.ts`, `useEncounterLive.ts`, `src/views/factions/FactionDetailView.vue`, `src/views/rules/RuleEditView.vue`, `src/views/crafting/CraftingRecipeView.vue`, `src/views/encounters/EncounterRunView.vue`)

- [x] DM preview faction view shows all factions, no member styling, and no "KNOWN MEMBERS" section — root cause: preview mode used `auth.linkedPartyMemberId` (null for DM) instead of `ui.dmPreviewPartyMemberId`; fixed by wiring preview party member ID, adding client-side filter to match player RLS, sorting member factions first, and green card styling for member factions (irongollem/grimoire#71)

- [x] Player view doesn't see faction they're a member of — `faction_party_members` had no player SELECT policy so `usePartyMemberFactions()` returned empty and "KNOWN MEMBERS" never showed; `factions` had no member-based SELECT policy so member-only factions were invisible; `usePlayerVisibleFactions()` also hard-filtered to `shared_with_players = true` client-side; fixed with two new RLS policies and removed the client-side filter (irongollem/grimoire#71)
