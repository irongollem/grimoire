# Fixes — Publishing & Export

Resolved bugs in the **Publishing & Export** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] Illustrated-sheet calibration-coupling bugs (found while hand-calibrating the recovered illustrated exporter). **(1) Edit layer unclickable** — the new drag-calibration layer in `/dev/sheet-calibration` had no z-index while `IllustratedSheet`'s own overlays sit at z-2/z-3, so real clicks fell through to sheet text (synthetic test events bypass hit-testing, which hid it); `z-10 select-none`, verified with a real `elementFromPoint` hit-test. **(2) Ability names overflowed their cells** on the Cinzel themes (classic/adventure/gothic) — CONSTITUTION/INTELLIGENCE spilled past the cell border; narrower modbox column + 10px/.01em name, verified 0px overflow via DOM `scrollWidth` measurement across all five themes. **(3) Skills list overflowed shorter painted panels** (gothic Letter clipped "Survival") — fixed rhythm replaced with grid `auto-rows: 1fr; height: 100%` so the 18 rows always divide the configured box height evenly; recalibrating a box now re-spaces the list instead of clipping it. **(4) Prose line-clamps were frozen authoring-time guesses** — `pTraits` stayed clamped at 3 lines inside boxes that hold 6 after recalibration; `clampStyle` now derives capacity from the box height (per-section line-height), with explicit `opts.lines` retained only as a deliberate stop-short-of-art override (51 stale `lines` opts stripped from the two configs, 10 art-avoidance ones kept). (`src/views/dev/SheetCalibrationView.vue`, `src/components/character-sheet/illustrated/IllustratedSheet.vue`, `sheetConfig.a4.ts`, `sheetConfig.letter.ts`)

- [x] The Interlude board + Card Forge UI polish (found in play-testing the new feature; all self-inflicted by this session's own new code). **(1) Card Forge source tabs.** `.source-panel` is a fixed `w-64` and `.source-tabs` was a single non-wrapping flex row with `overflow-hidden` — adding a 5th "Interlude" tab squeezed all five to ~51px each, crushing "Monsters"/"Interlude" and *clipping* the damage instead of revealing it. Now a `grid grid-cols-3` (two rows of three) with `truncate` + `bg-card` on the container so the one empty cell reads as part of the bar. **(2) "Stack the deck" field alignment.** The selects were `px-2 py-1 / rounded / bg-background` while `EntityCombobox`'s input is `px-3 py-1.5 / rounded-md / bg-card / font-fell`, so the three fields had different heights, corners and backgrounds; the combobox's label also sat higher because it was a bare `div` with no margin while the others were `label`s whose control carried `mt-1`. Every control now matches the combobox's metrics. **(3) The Prep button sat low** — `text-2xs` with no border vs the selects' `text-sm` *with* one, so at the same `py-1.5` it was ~8px shorter, and bottom-aligning a shorter control is what read as "oddly low"; `leading-5` + a transparent border give it the same box model. **(4) The "Recurring" line's odd word-spacing** was `flex gap-2` treating the inline `<em>always</em>` as a flex item, so the gap landed on *both* sides of the word; wrapped the sentence in one `span`. **(5) Filters were orphaned** — the Status/Character selects floated in a bare `div` *above* the heading of the list they filter and outside any card (the one section on the page that wasn't one). They now sit as a filter bar directly under the "Awaiting you" heading, inside the card. The status dropdown also rendered the raw enum (`pending`) when `DOWNTIME_DRAW_STATUS_LABELS` already existed for exactly this ("Awaiting the DM"). **(6) The party list lied while loading** — it rendered a confident "No characters in this campaign yet." whenever `party` was falsy, which includes the in-flight state, so landing on the board showed an empty party until a refresh warmed the cache. Loading and empty are different facts; the view now distinguishes them (`isPending`). `vue-tsc` + `vitest` (752) green. (`src/components/cardforge/CardForgeSourcePanel.vue`, `src/components/downtime/DeckBacksPanel.vue`, `src/views/downtime/DowntimeBoardView.vue`)

- [x] Card Forge backs rendered raw Tiptap JSON + raw dice HP for some monsters — ability descriptions stored as Tiptap docs (e.g. Annis Hag's Innate Spellcasting) printed `{"type":"doc",...}` on the card back because the composables passed `entry.description` straight through; and HP showed a bare roll expression (`10d10+20`) when the stat block lacked the usual `"75 (10d10+20)"` average. Fixed in `useMonsterCardData`/`useNpcCardData`: ability descriptions normalized via `extractTiptapText`, and HP takes the leading number when present else averages the dice via `parseDiceAvg` → `75`. Also tightened the back text 1px and gave it space-aware fitting so dense stat blocks stop clipping. (`src/composables/useMonsterCardData.ts`, `useNpcCardData.ts`)

- [x] Scriptorium auto-pagination collapsed multi-page documents to a single page whenever the preview was zoomed below 100%. The live Paged.js preview applies fit-to-width `zoom` to the render container; Paged.js measures the live DOM during layout but compares against the **unscaled** `@page` height it derived from CSS, so with zoom < 1 the scaled-down content always appeared to fit and overflow never spawned page 2. Only documents with an explicit `<hr>`/pageBreak paginated; pure auto-flow (e.g. a long inserted NPC) silently clipped to page 1 — reported as "638 words but only 1 page." Fixed by neutralising zoom to 1 while a render is in flight (`isPaging`) so Paged.js measures at natural scale, reapplying display zoom once the render settles; the slider and scroll dimensions are unaffected (`src/components/scriptorium/ScriptoriumPreviewPane.vue`). The spike never hit this because it rendered at natural size.

- [x] Broken-reactivity sweep (audit follow-up): `useScriptoriumDocument(id: string)` took a plain string, so its query key froze at setup — navigating document A→B (when the router reuses the editor component) showed document A's content at document B's URL. Changed to accept `Ref<string>` with a computed query key + reactive `enabled`, matching `useNote`/`useMonster`; caller passes the ref. (`src/composables/useScriptorium.ts`, `src/views/scriptorium/ScriptoriumEditorView.vue`)

- [x] Scriptorium 2024 ability score table overflowed its column in two-column layout — `table-layout: auto` + `white-space: nowrap` gave `.sc-ability-table--2024` a ~370px min-content width, wider than a two-column measure (~317px on A4); CSS multicol bleeds rather than clips, so the Save column spilled into the neighbouring column. Spotted during the Paged.js spike but latent in the live preview/PDF too (aggravated by the wider Alegreya body face). Fixed with `table-layout: fixed; width: 100%` + cell `overflow: hidden` in the shared theme CSS. (`src/assets/scriptorium/theme-base.css`)

- [x] Scriptorium PDF export silently dropped two-column layout — `buildPdfBlob` never applied the `phb-two-col` class to the page body and `RENDER_CSS` contained no `column-count` rule (only the orphaned column-span exceptions), so every two-column document exported as single-column while the preview showed two. Found during the Phase A theme-CSS unification (#454): preview and PDF now consume the same `src/assets/scriptorium/theme-base.css`, and `isTwoColumn` is threaded through `useScriptoriumPdf` → `buildPdfBlob` so the export body gets the same classes as the preview. (`src/composables/useScriptoriumPdf.ts`)

- [x] Scriptorium PDF export capped images at 380×480px while the preview didn't — a `img:not(.phb-border) { max-width:380px; max-height:480px }` rule existed only in the PDF's `RENDER_CSS`, so L (490px) and XL (650px) preset images rendered smaller in the exported PDF than in the preview. Eliminated by the Phase A single-source-of-truth CSS: both surfaces now share `.sc-theme img { max-width:100% }` and explicit node widths render identically. (`src/composables/useScriptoriumPdf.ts`, `src/assets/scriptorium/theme-base.css`)

- [x] Scriptorium PDF export injected a nonexistent `page-border.png` into every page — `buildPdfBlob` appended `<img class="phb-border" src="/assets/scriptorium/page-border.png">` but that asset was never shipped (only `page-background.webp` exists), so every export tripped the broken-image detector and showed a false "1 image failed to load and may be missing from the PDF" warning. Removed the dead border injection and its CSS. (`src/composables/useScriptoriumPdf.ts`)

- [x] Card Forge print layout ignored focal points — `FocalImage.computeCenteredPosition` returned generic defaults when `offsetWidth`/`offsetHeight` were 0 (print layout is `display:none` on screen); fixed by falling back to direct `${fp.x}% ${fp.y}%` when element dimensions are unavailable. Also wired missing `focal-point` props on Monster, Item, and Spell card components (irongollem/grimoire#53)

- [x] hitting print on cardforge when the chat is open instead sends the chat overlay to the printview

- [x] in tokenforge when clicking download, the downloaded image is only the top left half of the token

- [x] Print sheets in The Mint showing wrong content (coin sheet showed token sheet on first print after switching — `printMode` ref was updated but `window.print()` fired before Vue flushed the DOM; fixed with `await nextTick()`)

- [x] Scriptorium: navigating from document A to document B reused the ScriptoriumEditor component instance and never re-synced local metadata refs (title, theme, isTwoColumn, etc.) or Tiptap content, so document B inherited A's in-memory settings (irongollem/grimoire#365) — fixed by adding `:key="id || 'new'"` to `<ScriptoriumEditor>` in `ScriptoriumEditorView.vue`, forcing a full remount whenever the document ID changes.

- [x] Scriptorium Block Picker allowed inserting a Column Break in single-column documents where it silently does nothing (irongollem/grimoire#366) — `BlockEntry.enabled()` lacked a two-column guard for the Column Break entry. Extended `BlockEntry.enabled` signature to accept an optional context `{ isTwoColumn?: boolean }`; added `enabled: (_editor, ctx) => !!ctx?.isTwoColumn` to Column Break; `BlockPickerPanel` accepts a new `isTwoColumn` prop and passes it as context so the entry is greyed out and unclickable in single-column docs (`src/lib/scriptorium/blockRegistry.ts`, `src/components/scriptorium/BlockPickerPanel.vue`, `ScriptoriumEditor.vue`).

- [x] Scriptorium cover pages had no UI to set the background/art image despite the schema defining a `backgroundImage` attribute (irongollem/grimoire#367) — added a "Background Art URL" input to `CoverPageInspector.vue` for the front/inside and back variants, wired to the existing `backgroundImage` attribute via `reactive.local` and the watch that populates it from `getAttributes("coverPage")`.

- [x] Scriptorium cover page inspector `apply()` silently did nothing when the editor cursor was not on a coverPage atom node — `updateAttributes("coverPage", ...)` found no node, but the inspector still closed, giving false success feedback (irongollem/grimoire#368) — fixed by: (1) adding `isActiveCoverPage` computed (`editor.isActive("coverPage")`); (2) disabling the Apply button when false; (3) surfacing an inline hint ("Click inside a cover page node first, then apply.") that appears in the footer if Apply is clicked while inactive (`src/components/scriptorium/CoverPageInspector.vue`).

- [x] Scriptorium PDF export silently skipped broken images — html2canvas rendered blank areas with no user warning when images failed to load (irongollem/grimoire#369) — tracked failed images in `buildPdfBlob`'s `onerror` handler and exposed them as `pdfBrokenImages` from `useScriptoriumPdf`. `PdfPreviewDialog` now shows a red warning banner listing all failed URLs so the user knows the PDF may be incomplete before saving.

- [x] Scriptorium front cover art looked muted/filtered — the front-cover `<img>` was hardcoded to `opacity:0.55` so any author art was dimmed by default. Fixed by rendering the art at full strength and replacing the whole-image dim with a localized gradient scrim behind the title only (bottom third). The scrim is a new `titleScrim` cover attribute (default on) with a "Darken behind title" toggle in `CoverPageInspector` (front + has-art only), so authors of made-to-order art can turn it off. Unit-tested in `coverPage.test.ts` (`src/lib/tiptap/coverPage.ts`, `src/components/scriptorium/CoverPageInspector.vue`). Commit 056c30f.

- [x] Scriptorium page-furniture decorations couldn't be selected or dragged with a real mouse — "behind text" decorations (e.g. watercolor, default `under` layer) were rendered beneath the page content, and covers/the body-text layer (even transparent regions) painted on top with `pointer-events:auto`, so clicks never reached the decoration. Fixed in `renderFurniture` interactive mode by lifting every decoration above the page content (append last + high z-index) so it's always grabbable; true under/over layering still applies in the print/reader (non-interactive) render. Watermark's hit target narrowed to its text span. Also moved `FurnitureInspector` off the right-hand preview and made it draggable by its header (`src/lib/scriptorium/furniture/renderFurniture.ts`, `src/composables/useFurnitureEditing.ts`, `src/components/scriptorium/FurnitureInspector.vue`). Commits 15e21d8, 48d7106.

- [x] Scriptorium PDF/print export had an empty table of contents — `injectPagedToc` was only called in the live preview; the print path (`useScriptoriumPrint`) never filled the TOC, so exported PDFs showed an unpopulated `<nav data-type="toc">`. Fixed alongside #465 by moving to expand-then-fill (`expandTocPlaceholder` before layout + `fillPagedTocPages` after) and running both steps in the print path too (`src/lib/scriptorium/pagedToc.ts`, `useScriptoriumPrint.ts`). Commit 4281040.

- [x] Scriptorium PDF/print export rendered body text in fallback serif (not Cinzel/Alegreya) — the print iframe head injected the theme CSS but no `@font-face`, and fonts loaded in the parent document don't cross into a child iframe's font matching. Fixed by self-hosting Cinzel + Alegreya as TTF (`public/fonts/scriptorium/`) and injecting `src/assets/scriptorium/fonts.css` into the print head (#465). Commit c4bae46.

- [x] Scriptorium watercolor splatter assets showed a grey/white checkerboard — the PNGs were exported flattened (RGB, transparency checkerboard baked into the pixels, no alpha). Replaced with 9 proper-alpha `ink_asset_*.png` files wired through a single source of truth (`watercolorAssets.ts`); the splatter is painted as a CSS mask filled with the tint colour (so the Tint control works on the monochrome ink — a hue-rotate filter can't recolour black). Commits afc09f6, ef5de00, 0362199.
