# Fixes — Spells

Resolved bugs in the **Spells** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] Removed the fixed spell attack-bonus / save-DC override that three views rendered but nothing could ever set (#589) — `character_spells.fixed_attack_bonus` and `fixed_save_dc` were read by `grantAttackBonus`/`grantSaveDc` in `spellGrantStats.ts` and surfaced through `PlayerInnateSpells`, `PlayerMySpells` and `RunnerPcSpells`, but no insert or update anywhere wrote either column and both were 100% NULL in production — so a DM had no way to grant a fixed attack bonus or save DC on an innate spell. Found by the #580 all-NULL column audit, which classed them as the "UI reads something nothing populates" shape. Chose removal over finishing the feature. **Rendering is provably unchanged**: because both columns were always NULL, the `if (fixed_… not null)` branch could never fire, so execution always fell through to the existing `casting_ability` → class-stats → fallback chain, which is exactly what remains. The three templates never touched the fields directly either — they only call `attackBonusFor()`/`saveDcFor()` — so no template needed editing, and each still renders its Atk/DC affordance on the same `!== null` gate as before. Dropped both columns and their check constraints, and removed them from the `CharacterSpell` type and the now-dead test cases. (`src/lib/spellGrantStats.ts`, `src/types/spell.types.ts`, `supabase/migrations/20260730000009_drop_unsettable_spell_grant_overrides.sql`)

- [x] Long rest wiped stored spell slots for a multiclass caster with a non-caster legacy class (#526 item 5 of 7). `RestButtons.effectiveSpellSlots` returned `[]` as soon as `casterType === "none"` — derived from the legacy `member.class` — so a Rogue 3/Wizard 2 (class "Rogue") got no effective slots, the long rest wrote `spell_slots: []` (discarding the real multiclass slots), and the "All spell slots restored" summary lied. Fixed by honoring `member.spell_slots` FIRST (before the caster-type check), so any character with persisted slots keeps them; and defensively guarding both `RestDialog` writes (long-rest + Warlock pact) so an empty effective-slot list never overwrites the column. `vue-tsc -b` ok. (`src/components/player/RestButtons.vue`, `src/components/player/RestDialog.vue`)

- [x] Player character editor clobbered `spell_slots` for multiclass/custom casters (#514, High). `CharacterEditTabs` exposes editable `spellSlotMaxes` inputs, but the player-side `useCharacterCreationForm.save()` ignored them and unconditionally wrote `getDefaultSpellSlots(f.class, f.level)` — the single-class default table. So a player's slot edits never persisted; a multiclass caster (e.g. Paladin 5 / Warlock 3, legacy class "Paladin") had pact slots reset to the single-class table; and a **custom-class caster got `spell_slots: []`** (the default table has no entry), wiping every slot — triggered just by saving an unrelated field like Ideals. The DM's `PartyMemberForm` already persisted from `spellSlotMaxes`; the player copy had diverged. Fixed by building `spell_slots` from `spellSlotMaxes` exactly like `PartyMemberForm` (`{ level, max, used: max>0 ? existing.used : 0 }`, filtered to `max>0`); since `spellSlotMaxes` is seeded from the existing row via `buildSlotMaxes`, an untouched save now round-trips instead of overwriting. `vue-tsc -b` ok. (`src/composables/useCharacterCreationForm.ts`)

- [x] Subclass-granted spells (oath / domain / circle / Artillerist) counted toward the prepared-spell limit, pushing prepared casters over their cap — a level-3 Oath of the Ancients paladin showed 3/4 and an Artillerist artificer ran over its limit (reported by players, #458/#459). Added `character_spells.always_prepared` (migration `20260623000001`, with a `check (not always_prepared or is_prepared)` constraint). The prepared counter in `PlayerMySpells.vue` now excludes always-prepared spells (`is_prepared && !always_prepared`), and granted spells render a locked "Granted" badge — no prepare toggle, no remove — so a player can't accidentally unprepare an oath spell. Backfilled the two affected live characters (Speak with Animals; Shield + Thunderwave). Partial fix for #458/#459 — the full oath-spell granting workflow lands with the custom-subclass `granted_spells` feature.

- [x] Known-caster spell tab badge counted cantrips toward the spells-known max — `knownCount` was computed from all `character_spells` rows regardless of spell level, so picking cantrips reduced the displayed remaining slots in the "Known Bard 2/5" badge; fixed by switching to `useCharacterSpellsWithDetails` (returns full spell rows with level) and filtering: `knownCount` = level > 0 spells, `cantripCount` = level === 0 spells; badge now reads `2/5 + 1/4C` (spells/max + cantrips/max) when `cantrips_known` table is populated (`src/views/play/PlayerSpellsView.vue`)

- [x] Spell list empty for players, and "Add your first spell" button shown to players — `spells` RLS used a single `FOR ALL` policy (`auth.uid() = user_id`) so players (different auth.uid()) saw zero results; split into separate policies: SELECT allows campaign members to read spells owned by anyone in their campaign, INSERT/UPDATE/DELETE remain owner-only; also gated the empty-state CTA in `SpellList.vue` behind `!playerMemberId` (irongollem/grimoire#67)
