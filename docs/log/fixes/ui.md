# Fixes — UI & Layout

Resolved bugs in the **UI & Layout** area, newest first. Part of the Grimoire fix log — see the [log index](../index.md).

- [x] Dice-roller foldout was painted over by page content — the panel was `position: absolute` inside `AppSidebar`, but the sidebar is a `sticky` element (its own stacking context with `z-auto`), so the later-painted `<main>` sat on top of the panel's `z-40` no matter what; near the left screen edge the `right-0` anchor also pushed the panel off-screen. Fixed by `<Teleport>`-ing the panel + backdrop to `<body>` (escaping every page stacking context, so no page-level z-index is needed) and fixed-positioning it from the trigger's viewport rect, folding away from whichever screen edge it would overflow (flips left/right + up/down) and repositioning on resize/scroll. (`src/components/common/DiceRoller.vue`)

- [x] Soundboard card badges ("No Safari", "Retry") overflowed narrow cards (#464) — conditional badges on sound cards were rendered in a non-wrapping `flex` container, causing wide badges to overflow the card's right edge on narrow screens (especially mobile). Fixed by adding `flex-wrap` to the container so overflowing badges wrap to the next line; normal cards with short content remain single-line and are visually unchanged. (`src/components/soundboard/SoundCard.vue`)

- [x] Silent mutation failures had no user feedback (audit finding F-14 — the app had no toast system, only `useConfirm`). Added a lightweight toast system: `useToast()` (singleton stack, `error`/`success`/`info`/`fromError`) + `ToastHost.vue` (teleported bottom stack, auto-dismiss, themed to match ConfirmDialog), mounted once in `App.vue`. Wired `onError` toasts into 17 destructive mutations (delete note/npc/monster/quest/objective/quest-ref/faction/location/encounter/party-member/item/spell/campaign, remove-campaign-member, revoke-invite) so a failed delete now tells the user instead of failing silently — this also covers list-view delete buttons, not just the editors. The five editor delete handlers got a silent `catch` (failure already surfaced by the mutation's onError) so the post-toast rejection doesn't bubble as an unhandled error. Character-creation `save()` gained an outer catch that toasts (covers the rolled-back partial-creation path). Crafting deliberately has NO toast — `CraftAttemptDialog` already surfaces errors inline via `attemptError`, so a toast would double up. (`src/composables/useToast.ts`, `src/components/common/ToastHost.vue`)

- [x] Destructive-button safety (audit follow-up): delete buttons in the Faction, Encounter, Note, Quest, and Location editors either lacked an in-flight guard (double-click → two delete requests) or navigated away BEFORE awaiting the delete and swallowed the error (EncounterDetail pushed to the list then `await`ed in an empty catch, so a failed delete left the user on a stale list). All now use a `deleting` ref that disables the button, awaits the mutation, and navigates only on success; EncounterDetail's "Mark Done" toggle also gained an isPending guard against concurrent PATCHes. (`src/components/factions/FactionEditor.vue`, `encounters/EncounterDetail.vue`, `notes/NoteEditor.vue`, `quests/QuestEditor.vue`, `locations/LocationEditor.vue`)

- [x] "New update available" prompt overlapped the bottom button bar on app open (irongollem/grimoire#441) — a dismissible PWA update banner introduced in `0ebca42` floated over the fixed bottom nav. The root cause was already addressed in `fa858a7`, which removed the floating App.vue banner and moved the update action into a non-intrusive "Reload to update" button inside the "More" menus (`PlayerNavGrid.vue` for players, `DmNavMoreSheet.vue` for DMs), gated on `updateAvailable`. This pass cleaned up the leftover orphaned scaffolding from that move: removed the now-dead `--bottom-nav-h` CSS variable (set in `PlayerLayout.vue` solely to position the removed banner, read nowhere) along with its now-unused `onMounted`/`onUnmounted` imports, and corrected the stale doc comment in `useAppUpdate.ts` that still pointed at the App.vue banner.

- [x] Campaign switcher disappeared on mobile / iOS PWA for DMs — it only ever lived in `AppSidebar.vue`, which is `hidden md:flex`, and was never actually wired into the mobile DM navigation despite a prior intent to "put it in the more bar". Mobile DMs (bottom bar → "More") had no way to see or switch the active campaign. Fixed by embedding the existing self-contained `CampaignSwitcher.vue` at the top of `DmNavMoreSheet.vue` (full-bleed `-mx-4` to align with the sheet's title divider), so the active campaign, switcher dropdown, archived list, create, claim, and import actions all return on mobile/PWA. (`src/components/layout/DmNavMoreSheet.vue`)

- [x] Mobile nav FAB (hamburger) was inaccessible while NPC/Monster visibility popovers were open — the popovers use `fixed inset-0 z-50` backdrops that covered the FAB at `z-40`. Raised FAB to `z-[60]` in `AppTopBar.vue`. (#412)

- [x] NPC and Monster edit views caused horizontal bleed on mobile — grid/flex children without `min-w-0` refuse to shrink below content size. Added `min-w-0 max-w-full` to `NpcDetail` form root and right-column div, and to `MonsterDetail` root div. (#413)

- [x] Loading or pasting content with link marks in the Tiptap editor froze the browser — root cause was the `autolink` plugin (enabled by default) which scans every ProseMirror transaction for URLs and creates new link marks, triggering another transaction in an infinite loop; fixed by stripping link marks entirely: `stripLinkMarks()` removes them from JSON on load, `transformPastedHTML` unwraps `<a>` tags on paste (keeping text), and the `watch` on `modelValue` was removed since it was not needed (description is only ever changed by the editor itself) and had been the source of several secondary echo-loop attempts (`src/components/common/RichTextEditor.vue`)

- [x] Rich text editor two-column layout toggle not persisted — `twoColumn` was a local `ref(false)` that only applied a CSS class at runtime and was never serialised into the Tiptap JSON, so the layout was lost on reload; fixed by extending the Tiptap `doc` node with a `twoColumn` attribute (`CustomDocument`), writing it via `updateAttributes('doc', …)` on toggle, and syncing the ref back in `onCreate`/`onUpdate` so saved content carries the layout setting (`src/components/common/RichTextEditor.vue`)

- [x] TagInput multi-tag batch bug

- [x] entity combobox (reward items, locations, NPCs, etc.) dropdown not appearing when typing — dropdown was `position: absolute` inside a card container with `overflow: hidden` + `border-radius`, which clips absolutely-positioned descendants in modern browsers. Fix: teleport dropdown to `<body>` with `position: fixed`, recalculate coordinates from `getBoundingClientRect()` on open and on scroll (capture phase); also flips upward when near the bottom of the viewport.

- [x] DM nav had two links to the same page — both **Party** and **Publish → Character Sheet** pointed at `/party`, so the Character Sheet item never reached a sheet (it dumped you on the party list to "pick a member first" because the export view required a `:partyMemberId`). Gave the exporter a member-agnostic entry point instead: new `/character-sheet` route (`character-sheet-picker`, alongside the existing `/character-sheet/:partyMemberId`) and `CharacterSheetView` now renders an `EntityCombobox` character picker that seeds from the route param when present and otherwise defaults to the first party member; the export panel is keyed on the member so its per-character prefs reload on switch. Nav "Character Sheet" retargeted `/party` → `/character-sheet`. (`src/lib/nav.ts`, `src/router/routes.ts`, `src/views/publishing/CharacterSheetView.vue`)
